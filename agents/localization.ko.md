# 로컬라이제이션 지침 — 맥락을 읽고 옮깁니다

코드·Figma에서 **문자열과 그 맥락을 읽고**, `i18n/` 규약에 맞게
로컬라이제이션하는 절차입니다.

전제: `i18n/README.md`를 먼저 읽으세요 (BCP 47, 키 명명, ICU, 길이 예산, RTL).
이 문서는 규약을 반복하지 않고 **맥락을 읽는 방법과 판단 순서**만 다룹니다.

> **(2026-08-18 자체 검증 반영)** 이 지침을 코퍼스 자체 자산(`i18n/`)에
> 돌렸습니다 — 결과는 `agents/case-studies/i18n-selfcheck.md`.
> 막혔던 자리를 아래 "(2026-08-18 자체 검증 반영)" 표기 항목으로 고쳤습니다.
> **제품 맥락 판단(문자열 추출, 레이아웃 실측 기반 `maxLength`, 용어집 확정 루프,
> RTL 코드 전환)은 대상이 없어 여전히 미검증입니다** — 절차 1을 처음 제품에
> 돌릴 때 다시 기록하세요.

## 원칙

1. **번역은 문자열 교체가 아니라 레이아웃·문법 작업입니다** (i18n README 서두).
   문자열만 바꾸고 끝내지 않습니다 — 길이·복수형·방향 리스크를 함께 냅니다.
2. **기계 번역 결과는 제안입니다.** 산출물에 네이티브 검수 전제를 명시합니다.
3. **용어를 먼저 고정합니다.** 제품 고유 명사·기능명 목록(용어집)과
   `doNotTranslate` 목록을 만들어 **사용자 확인을 받은 뒤** 본 번역에 들어갑니다.
   용어가 흔들리면 전체를 다시 해야 합니다.

## 절차

### 1. 문자열 추출 — 어디를 봐야 하나

**코드에서** 하드코딩 문자열이 숨는 자리 (JSX 텍스트만 보면 절반을 놓칩니다):

```
JSX/템플릿 텍스트         placeholder= / label= / title=
aria-label / alt          에러 메시지 (throw·toast·validation)
빈 상태·로딩 문구          confirm()·다이얼로그 본문
날짜·숫자 직접 포맷        문자열 이어 붙이기(`${count}개`) — ICU 전환 대상
```

**Figma에서:** 텍스트 노드를 화면 단위로 수집하되, **컴포넌트 변형에만 있는
문자열**(에러 상태의 헬퍼 텍스트 등)을 놓치지 않도록 상태 variant까지 봅니다.

### 2. 키 설계 — 맥락이 키에 담깁니다

`<화면>.<요소>.<용도>` (규약). 화면명은 라우트/프레임에서 가져와
이벤트 시트의 `screen_name`과 **같은 정규화를 씁니다** — 두 산출물이 같은
화면을 다른 이름으로 부르지 않게 합니다 (`agents/event-instrumentation.md`).

**같은 표기라도 문법 역할이 다르면 키를 나눕니다** — `close`(동작) vs
`closed`(상태)가 규약의 예시입니다. 추출 단계에서 각 문자열에
**품사/역할(버튼 동작·상태 표시·제목·문장)**을 기록해 두면 이 판단이 기계적이 됩니다.

**화면 횡단 문자열은 `common.<요소>.<용도>`에 둡니다** (2026-08-18 자체 검증 반영).
`<화면>` 자리에 실제 화면이 없는 경우의 규칙이 없어 막혔던 자리입니다.
버튼 라벨 "닫기"처럼 **여러 화면에서 문법 역할이 완전히 같은 것만** `common`에
올리고, 맥락이 조금이라도 다르면 화면별로 분리합니다("흔한 오판" 표).
`common`에 올린 키는 화면 정보가 사라지므로 **맥락 메타데이터가 필수**입니다(§3).

**세그먼트 수는 3단이 규약이고 린터는 2단부터 통과시킵니다**
(2026-08-18 자체 검증 반영, `i18n/lint.mjs:134`). `checkout.total`처럼
요소·용도가 하나로 합쳐지는 경우가 실제로 있으므로 2단이 곧 위반은 아니지만,
**린터 통과가 3단 규약을 지켰다는 증거는 아닙니다** — 직접 확인하세요.

### 3. 맥락 메타데이터를 함께 만듭니다

번역자(사람이든 모델이든)가 원문만 보고 오역하는 지점을 메타데이터로 막습니다:

```json
{
  "home.cta.primary": { "context": "버튼 라벨, 온보딩 시작 동작", "maxLength": 8 },
  "chart.legend.cycle": { "context": "차트 범례, 명사", "doNotTranslate": ["Acme"] }
}
```

- `maxLength`는 **레이아웃 실측**에서 옵니다 — 버튼 폭·탭 라벨 영역을 Figma에서
  재고, i18n README의 길이 예산 표(짧은 문자열 200~300% 확장)를 적용합니다.
- 버튼·탭 라벨은 전부 위험 목록에 올립니다 — 가장 많이 터지는 자리입니다.

**메타데이터는 린터가 읽지 않습니다** (2026-08-18 자체 검증 반영).
`i18n/lint.mjs`에 메타데이터 경로가 없어 `maxLength`를 선언해도 검사되지 않고,
코퍼스에 템플릿도 실물 예시도 없습니다. **위 형식을 그대로 쓰고,
파일명은 `<로케일>.meta.json`이 아니라 `meta.json` 한 벌로 두세요** —
맥락은 로케일과 무관하고, `*.json` 글롭 린트에 걸리면 로케일 파서가
파일명을 언어 코드로 읽어 오탐이 납니다(§5).

**`doNotTranslate`의 위치는 키별 배열입니다** (2026-08-18 자체 검증 반영).
`i18n/README.md`의 "번역하지 않는 것" 절은 파일 단위 목록으로 읽히지만,
브랜드명이 어느 문자열에 들어 있는지를 번역자가 알아야 하므로 **키별로 답니다.**
제품 전역 목록이 따로 필요하면 메타데이터 파일 최상위에 `_global` 항목으로 둡니다.

**메타데이터가 없으면 기준 파일만으로 구분 불가능한 키가 생깁니다.**
코퍼스의 `en-US.json`은 `common.action.close`와 `common.state.closed`가
**둘 다 `"Close"`** 입니다(README가 밝힌 의도된 표본). 린터는 기준 파일 내부의
동일 값 중복을 검사하지 않으므로, **이 오역은 메타데이터로만 막힙니다.**

### 4. 언어별 판단

- **한국어:** 어미 통일이 최우선입니다. 기존 문자열에서 톤(해요체/합쇼체/명사형)
  을 **관찰해서 따르고**, 기존 문자열이 없으면 사용자에게 묻습니다 —
  임의로 정하지 않습니다. 조사(을/를, 이/가)가 붙는 변수 삽입은 문장 재구성으로
  회피하는 것을 우선하고, 불가피하면 메타데이터 `context`에 표시합니다
  (문자열 JSON에 비고 필드가 없습니다 — 2026-08-18 자체 검증 반영).

  **관찰 단위는 셋입니다** (2026-08-18 자체 검증 반영) — 어미 등급 · **문말 구두점** ·
  고정 인사말. 코퍼스 `ko-KR.json`에도 "{userName}님 안녕하세요"(해요체·마침표 없음)와
  "카드가 거절되었습니다."(합쇼체·마침표 있음)가 공존합니다.
  **인사말·감탄사 같은 관용구는 어미 통일 대상에서 뺍니다**(관용형이 곧 자연스러운
  형태입니다). 대신 **문말 구두점은 문장 유형별로 통일하고 그 결정을 리스크 리포트에
  적으세요** — 린터에 톤·구두점 검사가 없어 여기서 놓치면 아무도 잡지 않습니다.
- **CJK ↔ 서구 언어:** 길이가 양방향으로 다릅니다 (한국어는 영어의 50~70%,
  독일어는 그 반대). **기준 언어 하나로 레이아웃을 잡았는지**를 리스크로 보고합니다.

  **축소 방향은 린터가 재지 않습니다** (2026-08-18 자체 검증 반영).
  `lint.mjs`의 길이 예산은 **상한만** 검사하므로(`expansionBudget` + `ratio > budget`),
  한국어가 영어의 36%로 줄어도 위반 0건입니다 — 코퍼스 `ko-KR.json`의
  `home.cta.primary`(36%)·`common.action.close`(40%)가 실제로 그렇습니다.
  **버튼·탭 라벨의 축소율을 손으로 계산해 50% 미만인 키를 리스크 리포트에 올리세요**
  (여백 과다·정렬 붕괴가 나는 자리입니다).

  본문 글자 크기 관행도 다릅니다 — `design-systems/patterns/typography.md`
  **"본문 기본 크기" 절과 그 아래 68표본 재종합**을 읽으세요
  (2026-08-18 자체 검증 반영). **이전 판은 "14px CJK / 16px 서구 웹 / 17pt iOS"라고
  3분류로 요약했는데, 재종합에서 6개 진영으로 갈렸고 그 3분류는 성립하지 않습니다** —
  17px 진영이 Apple·KRDS(한)·디지털청(日)으로 **셋 다 CJK 문맥**이고,
  16px 진영에 Charcoal(pixiv)·Serendie(三菱電機)·SmartHR 같은 일본 표본이 있습니다.
  **숫자를 여기 옮겨 적지 말고 그 문서의 재종합 절을 인용하세요**
  (`agents/design-review.md`와 같은 규율입니다).
- **RTL 대상 포함 시:** 문자열 밖 작업이 생깁니다 — 방향성 아이콘, 논리 속성
  (`margin-inline-start`) 전환 여부를 코드에서 확인하고 별도 절로 보고합니다.
  뒤집지 말아야 할 것(재생 버튼, 숫자, 로고)은 i18n README RTL 절 기준.
  코퍼스 표본 (2026-08-18 자체 검증 반영 — 파일·행을 확인해 정정했습니다):

  | 표본 | 무엇 | 근거 |
  |------|------|------|
  | shadcn/ui | `--font-ar`·`--font-he` 언어별 서체 토큰 (코퍼스 유일) | `patterns/typography.md` "계열 분리" 표 |
  | Mantine | `border-end-end-radius`(버튼 그룹) · `inset-inline-start` 트랜지션(Switch) | `patterns/button.md` "버튼 그룹" 절 · `patterns/form.md` "Switch" 절 |
  | Cloudscape | `border-width-alert-inline-*` — 토큰 **이름**이 논리 속성 | `patterns/feedback.md` "얼럿 치수" 절 |

  **이전 판의 "Radix Themes가 논리 속성을 씁니다"는 근거가 없어 뺐습니다** —
  `systems/radix-themes.md`에 논리 속성·RTL 언급이 없습니다.
- **복수형:** 대상 로케일의 CLDR 카테고리 수(README 표)를 채웁니다.
  한국어 `other` 하나, 아랍어 6개 — 빈 카테고리는 린터가 잡습니다.

### 5. 검증하고 넘깁니다

```bash
node i18n/lint.mjs i18n/ko-KR.json --against i18n/en-US.json --strict
```

**경로와 `--strict` 둘 다 필요합니다** (2026-08-18 자체 검증 반영).
이전 판은 `node i18n/lint.mjs ko-KR.json --against en-US.json`이었는데
스크립트에만 접두사가 붙어 있어 저장소 루트에서 `ENOENT`로 실패합니다.
**대상 파일과 기준 파일에도 같은 접두사를 붙이거나, `i18n/`에서 실행하세요.**

**`--strict` 없이는 위반이 있어도 exit 0입니다** (`lint.mjs:300`).
`event-taxonomy/convert.mjs --lint-only`는 반대로 `--strict` 없이도 exit 1이므로
(`agents/event-instrumentation.md` §6), **두 도구를 같은 스크립트에 넣을 때
관례가 다르다는 것을 알고 쓰세요.** 종료 코드로 통과를 판정한다면 `--strict`는 필수입니다.

**`--against`를 생략하지 마세요.** README의 CI 예시(`node lint.mjs *.json --strict`)는
기준 비교가 없어 **번역 누락·플레이스홀더 일치·길이 예산·미번역 잔존 4종이 통째로
빠집니다.** 또 `*.json` 글롭은 `template.json`을 함께 집어 로케일 파서가
파일명을 언어 코드로 읽고 오탐을 냅니다 — **로케일 파일만 명시적으로 넘기세요.**

기준(`--against`)은 **영어 파일**입니다 (길이 예산이 영어 기준 — README).
기준이 영어가 아니면 스크립트가 경고를 내고, 거짓 양성이 실제로 발생합니다.

**린터가 잡지 않는 것은 손으로 확인합니다** (2026-08-18 자체 검증 반영).

| 축 | 린터 | 사람이 확인할 것 |
|----|:----:|------------------|
| 길이 **축소** (CJK) | ✗ | 상한만 검사 — §4 |
| 톤·어미·문말 구두점 | ✗ | §4 |
| 키 세그먼트 3단 | △ | 2단부터 통과 — §2 |
| 기준 파일 내부의 동일 값 중복 | ✗ | 맥락 메타데이터로 해소 — §3 |
| `maxLength` 준수 | ✗ | 메타데이터를 읽지 않습니다 — §3 |
| RTL 코드 전환 | ✗ | 문자열 밖 작업 — §4 |

산출물 구성:

- 로케일별 JSON (플랫 키 + ICU)
- 맥락 메타데이터 파일 (`meta.json`)
- **리스크 리포트** — 길이 초과 위험 키, **축소율 50% 미만 라벨 키**,
  조사 삽입 키, RTL 잔여 작업, 톤·구두점 결정 근거(관찰인지 질문 답변인지)
- **질문 목록** — 용어집 미확정 항목, 톤, 지역 표기(통화·단위) 정책

## 흔한 오판 (하지 말 것)

| 오판 | 바른 처리 |
|------|-----------|
| 번역문을 키로 사용 | 구조 키 (`home.cta.primary`) |
| `count === 1 ?` 하드코딩 | ICU plural |
| 한 키를 여러 화면에서 재사용 | 맥락 다르면 분리 |
| 날짜·통화를 문자열에 포맷해 넣기 | ICU 인자 (`{when, date, medium}`) |
| 어미를 문자열마다 다르게 | 기존 톤 관찰 → 통일, 없으면 질문 |
| `kr`·`cn` 로케일 코드 | BCP 47 (`ko`, `zh-Hans`) — 린터가 잡지만 만들지도 말 것 |
| 원문에 없는 정중함/설명 추가 | 원문 정보량 유지, 제안은 비고로 |
