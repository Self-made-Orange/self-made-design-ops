## 2단계 — 절차 자체의 결함

### E1. 원칙 4와 절차 6이 서로 배타적입니다 (핵심)

원칙 4는 "미확정 enum은 규약대로 `…`를 남깁니다", 절차 6은 "통과한 CSV"를 냅니다.
그런데 린터는 `…`를 **규약 위반으로 보고**합니다 (`convert.mjs:131-132`).
**둘 다 만족하는 산출물이 존재하지 않습니다.**

`event-taxonomy/README.md`도 한 문서 안에서 갈립니다.

| 위치 | 문장 | 의미 |
|------|------|------|
| "검토 항목" | "enum 값이 미정인 곳에 `…` 표시가 **있는가**" | 있어야 정상 |
| "린터" | "enum에 미확정(`…`) 표시가 **남아 있는가**" | 있으면 지적 |
| `convert.mjs:132` | `enum 값이 미확정입니다 (…)` → `problems`에 push | 위반 |

`…`는 **위반이 아니라 잔여 작업 알림**입니다. 지침이 이 성격을 명시하고,
`--strict` 게이트에서 빠져야 합니다.

### E2. 원칙 1(측정 목적)에 둘 자리가 없습니다

지침은 "비고 컬럼 또는 별도 목록"에 적으라고 합니다. 둘 다 실패합니다.

**비고에 적으면 조건 컬럼이 오염됩니다.** probe 실행:

```csv
온보딩,onboarding_view,온보딩 > [screen_name],온보딩 화면 진입,screen_name,"welcome | complete",필수 · 목적: 단계별 이탈 관측
```

```json
"required": true,
"condition": "필수 · 목적: 단계별 이탈 관측"
```

`convert.mjs:92`의 `r.note.replace(/^필수$/, '')`는 **비고가 정확히 `필수`일 때만**
지웁니다. 목적을 덧붙이면 `필수`가 조건 컬럼에 그대로 남아 md·html·Notion 전 타깃에
"조건: 필수 · 목적: …"으로 출력됩니다.

**8번째 컬럼을 만들면 조용히 삭제됩니다.** `COLS`가 7개로 고정(`convert.mjs:19`)이라
린터는 `위반 없음`을 내고 JSON 출력에 목적 문자열이 0건 남습니다.

### E3. "초안 — 검토 필요" 표시가 변환에서 사라집니다

원칙 4가 요구하는 표시를 CSV에 담을 컬럼이 없고, `toMarkdown`·`toHtml` 모두
초안 상태를 렌더링하지 않습니다 (출력 grep 각 0건). **초안이 확정본과 구별 불가한
형태로 유통됩니다.**

### E4. 절차 4의 퍼널 절이 어디에도 자리가 없습니다

지침은 `sdk_view(scan_qr) → sdk_view(device_found)` 표기의 퍼널 절을 요구하지만,
CSV 컬럼에도 변환기에도 퍼널 개념이 없습니다(출력 내 "퍼널" 0건).
지침이 "시트와 별도로" 두라고 했으므로 형식상 모순은 아니나, **별도 문서의 형식이
어디에도 정의돼 있지 않아 즉흥 판단이 필요했습니다.**

### E5. 린터가 규약 필수 항목 3개를 검사하지 않습니다

`README.md`의 검토 항목 7개와 구현을 대조했습니다.

| 검토 항목 | 구현 | 근거 |
|-----------|------|------|
| 이벤트명 `{도메인}_{동작}` | ✓ | `convert.mjs:115` |
| 카테고리 ↔ 접두사 일치 | **△ 약화** | 같은 카테고리에 다른 도메인이 섞였을 때만 검출. **identity는 미검사** — `온보딩`/`onboarding`이 통과합니다 |
| 화면 단위로 이벤트를 쪼개지 않았는가 | **✗ 미구현** | 검사 코드 없음 |
| 조건부 프로퍼티에 조건 명기 | ✓ | `convert.mjs:127` |
| 필수 프로퍼티에 `필수` 표기 | △ | 위 항목과 합쳐짐 |
| enum 미정에 `…` | **✗ 역방향** | E1 |
| 제품 고유 데이터 혼입 | ✗ | 기계 검사 불가 — 사람 판단 |
| (컬럼 표) 화면 위치 **필수** | **✗ 미구현** | probe에서 `화면 위치` 공란이 `위반 없음` 통과 |

**역방향 카테고리 검사가 없습니다.** probe 실행:

```csv
온보딩,onboarding_view,온보딩,진입,screen_name,"welcome",필수
설정,onboarding_view,설정,진입,screen_name,"pref",필수
```
```
위반 없음.
exit=0
```

README가 "도메인이 다르면 이벤트를 분리합니다"라고 못박은 형태 — 두 카테고리가
한 이벤트명을 공유하는 것 — 이 그대로 통과합니다.

### E6. 카테고리가 조용히 유실됩니다 (변환기 버그)

같은 이벤트명이 **다른 카테고리에서 화면 위치 없이** 이어지면
`normalize`의 `isNew` 조건(`convert.mjs:69-70`)이 거짓이 되어 앞 이벤트에
프로퍼티로 병합됩니다. probe 실행 결과 `설정` 카테고리 행이 통째로
`온보딩`/`onboarding_view`의 두 번째 `screen_name` 프로퍼티가 되고,
`카테고리`·`트리거` 값은 `convert.mjs:82-84`의 `&& !current.category` 가드에
막혀 **버려집니다. 경고 없음, 종료 코드 0.**

지침이 §3에서 화면·버튼을 enum으로 밀어 넣으라고 하는 만큼 화면 위치를 비우는
편집이 흔하므로, 실무에서 밟기 쉬운 자리입니다.

### E7. 90행 마크다운 표가 깨져 있습니다

```
| 뒤로가기·닫기 무시 | 퍼널 이탈 관측에 필요하면 `button_name: back | close`로 포함 |
```

2열 표에 셀이 3개입니다. 코드 스팬 안의 파이프도 표 셀을 나눕니다.
**정작 `convert.mjs`의 `mdCell()`(143~144행)은 같은 이유로 파이프를 이스케이프합니다** —
도구가 아는 것을 지침 문서 자신이 어겼습니다.

### E8. 종료 코드 계약이 지침에 없습니다

`convert.mjs --lint-only`는 `--strict` 없이도 위반 시 exit 1입니다 (`convert.mjs:368`).
반면 `i18n/lint.mjs`는 `--strict` 없이는 위반 12건에도 **exit 0**입니다
(`lint.mjs:300`, `i18n-selfcheck.md` L2 참조). **두 도구의 관례가 반대인데
어느 지침도 이를 적지 않습니다.** CI·에이전트가 종료 코드로 판정하면 한쪽이 조용히 통과합니다.

## 위반 0건으로 끝난 항목

억지로 문제를 만들지 않기 위해 적습니다.

- **PII 프로퍼티 (원칙 3)** — `example.csv` 11개 프로퍼티 전부 비PII. `query_length`가
  검색어 원문 대신 길이를 쓰는 파생값 처리의 표본입니다
- **`template.csv`** — 린터 통과, `--to json` 정상 (`{"events": []}`)
- **그룹핑·평면화** — 조건부 이어짐 행 → 이벤트 객체 → 5개 타깃 렌더 전부 정상
- **`--strict` 게이트** — 위반 시 변환 중단 + exit 1 정상

## 확인 못 한 것

- **Figma 경로 (§1)** — `get_metadata`로 프레임을 열거하는 절차. 코퍼스에 Figma 파일이
  없어 미실행. 상태 변형 → 프로퍼티 승격 규칙도 미검증
- **enum 값 정규화 (§3)** — "3-2. 기기 연결 완료 ✅" → `device_connected` 변환.
  입력이 없어 미실행
- **카테고리 도출 (§2)** — 내비게이션 구조에서 3~6개를 뽑는 판단. 화면 소스 없음
- **커버리지 선언·질문 목록 (§6)** — 형식이 코퍼스에 정의돼 있지 않아 산출 대상이 없음

## 부수 발견 — 도구의 사소한 결함 1건

`toMarkdown`의 요약 표 헤더가 `| 카테고리 | 이벤트 | 프로퍼티 수 |`인데
두 번째 열의 값은 이벤트 **개수**입니다 (`convert.mjs:154-156`). `이벤트 수`가 맞습니다.
