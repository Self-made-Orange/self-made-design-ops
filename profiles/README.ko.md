# profiles/ — 제작 지시서 계층

`design-systems/`가 **"다들 이렇게 했다"(기술)**라면, 여기는
**"이렇게 만들어라"(규범)**입니다. 산출물은 에이전트가 그대로 읽는
`DESIGN.md` 형식이며, 포맷 상세는 `design-systems/INTEROP.md`에 있습니다.

## 왜 층을 나누는가

코퍼스의 핵심 규율은 **추측 금지 · 출처 고정**입니다. 그런데 제작 지시서는
본질적으로 **결정**을 담아야 합니다 — 표본이 갈리는 축에서 하나를 골라야 하고,
색처럼 표본에 답이 없는 축도 채워야 합니다.

두 성격을 한 파일에 섞으면 **관측이 오염**됩니다. 그래서 층을 나누고,
**모든 값에 근거 등급을 답니다.**

## 근거 등급 — 4종

| 등급 | 뜻 | 예 |
|:---:|------|-----|
| **M** (measured) | 코퍼스에 실측 표본이 있음 | 스페이싱 4·8·16 (61표본) |
| **D** (derived) | 실측에서 파생·보간 | 본문 16px에서 만든 제목 스케일 |
| **A** (authored) | **저자 판단** — 표본 근거 없음 | 브랜드 색, 톤, 곡률 취향 |
| **U** (unverified) | **의도적 공백** — 채워야 할 자리 | tv 타이포(코퍼스에 실측 없음) |

**A와 U를 숨기지 않는 것이 이 계층의 전부입니다.** 지시서가 "전부 근거 있음"인
척하면 코퍼스의 신뢰가 같이 무너집니다.

## 두 하위 계층

| | `measured/` | `interpreted/` |
|---|---|---|
| 성격 | **코퍼스 파생** — M·D가 대부분, A 없음 | **저자 해석** — A가 주성분 |
| 축 | 플랫폼·밀도 (web·touch·tv) | 스타일·톤 (분위기) |
| 생성 | `design-systems/to-design-md.mjs`로 재생성 가능 | 손으로 씀 |
| 색 | **비움**(U) — 코퍼스에 권장 팔레트 없음 | **채움**(A) — 그게 존재 이유 |
| 쓰임 | 뼈대 | 살 |

**둘을 겹쳐 쓰는 것이 정상 사용법입니다** — `measured/`로 구조를 잡고
`interpreted/`(또는 제품 브랜드)로 색·톤을 덮습니다.

## `measured/` — 현재 4종

| 파일 | 프로필 | 핵심 근거 |
|------|--------|-----------|
| `web-comfortable.DESIGN.md` | 웹 데스크톱 | 버튼 40px(77표본 최빈) · 본문 16px |
| `web-compact.DESIGN.md` | 밀집 관리 화면 | 본문 14px(17표본 진영) |
| `touch-mobile.DESIGN.md` | 터치 | 버튼 48px(Material 48dp ∩ Apple 48pt) |
| `tv-wall.DESIGN.md` | 벽·TV (3m) | 오버스캔 60/80pt · 포커스 간격 60pt · **타이포는 U** |

재생성:

```bash
node design-systems/to-design-md.mjs --profile tv --name "제품명" -o DESIGN.md
npx @google/design.md lint DESIGN.md     # 4종 모두 오류 0·경고 0 확인 (2026-08-18)
```

## `interpreted/` — 현재 1종

| 파일 | 무엇인가 | 주요 저자 값 |
|------|----------|--------------|
| `self-made-designops-site.DESIGN.md` | **이 코퍼스 자신의 사이트** | 팔레트 전체(테마 둘) · Pretendard · 248px 레일 · CTA |

사이트는 이 저장소가 실제로 만든 첫 물건이니, 저장소가 남들에게 요구하는 산출물을 자기도
내놔야 합니다. `measured/`가 아니라 여기 있는 이유는 위 표가 말하는 그대로입니다 —
**색이 채워져 있고**, 행 대부분이 A입니다.

**쓰는 게 아니라 생성합니다** — `site/design-spec.mjs`가 `docs/assets/site.css`를 읽어
스펙을 씁니다. 둘이 어긋날 수 없게요. 손으로 쓴 스펙과 손으로 쓴 스타일시트는 진실 공급원이
둘인 상태이고, 그게 이 저장소가 잡으려는 실패입니다. 생성기는 찍는 대비값도 전부 **계산**하므로
문서의 숫자가 문서의 색과 어긋날 수 없습니다. 기대한 선언이 없으면 그럴듯한 숫자를 내놓는 대신
실패합니다.

```bash
node site/design-spec.mjs                # 영어 프라이머리
node site/design-spec.mjs --lang=ko      # 한국어판
npx @google/design.md lint profiles/interpreted/self-made-designops-site.DESIGN.md
# 오류 0, 경고 1 (2026-08-22)
```

**경고 하나는 결함이 아니라 요점입니다.** `contrast-ratio`가 CTA에서 걸립니다 —
`#ff5926` 위의 `#ffffff`가 3.13:1로 AA 아래입니다. 소유자의 의도된 브랜드 결정이고, 스펙에
A 행으로 적혀 있으며, 린터가 독립적으로 같은 결론에 도달한 건 이 계층이 작동한다는 뜻입니다.
대가를 치르는 저자 값이 팔레트 안에 숨는 대신 그 대가를 스스로 알립니다.

`.github/workflows/site.yml`이 `site/`·`docs/`·`profiles/interpreted/`를 건드리는 모든 PR에서
양쪽 언어판을 재생성하고, 커밋본과 다르면 실패시킵니다.

**`tv-wall`이 이 계층의 성격을 가장 잘 보여줍니다** — 안전 영역·포커스 간격은
실측(M)이라 값을 주고, 타이포는 코퍼스에 없어서(U) **비운 채 검증 절차만**
적습니다. 그럴듯한 숫자로 메우지 않습니다.

## 규칙

1. **A 값에는 근거 대신 의도를 적습니다.** "왜 이 값인가"를 못 적으면 그 값은
   지시서에 넣지 마세요.
2. **U는 비운 채로 넘깁니다.** 채우는 절차(무엇을 어떻게 확인하면 되는지)를
   함께 적습니다.
3. **M·D 값이 코퍼스와 어긋나면 코퍼스가 이깁니다.** 코퍼스가 갱신되면
   `measured/`는 재생성 대상입니다.
4. **제품 고유 값은 여기 두지 않습니다.** 제품 저장소의 `DESIGN.md`로 갑니다
   (제품 데이터 반입 금지 원칙).
5. **린터를 통과시킨 뒤 커밋합니다** — `npx @google/design.md lint`.
   단 **통과가 완성은 아닙니다**(빈 색을 린터가 잡지 않음 — `INTEROP.md`).
