DesignOps starter kit

Clone it once.
Make your DesignOps.

Conventions, linters and agent procedures for the work that repeats between design and development — 5,630 lines of it, no dependencies, nothing to install. Every default in it is measured across 116 design systems, not remembered.

Start in three commands Get DESIGN.md See what's inside

Three commands

No package, no build step, no runtime. It is a directory you clone next to your project and point your agent at.

01

Clone it beside your project

Anywhere your agent can read. .design-ops/ keeps it out of the way.

02

Point the rules file at it

CLAUDE.md, AGENTS.md, .cursorrules, copilot-instructions.md — the wording is tool-neutral.

03

Generate the build spec

A DESIGN.md your agent builds from, with an evidence grade on every value.

Copy this

# 01 — clone
git clone --depth 1 https://github.com/Self-made-Orange/self-made-design-ops .design-ops

# 02 — add to your agent's rules file
#   · picking a reference system → .design-ops/agents/system-selection.md
#   · reviewing a design or build → .design-ops/agents/design-review.md
#   · evidence for any single value → .design-ops/design-systems/patterns/*.md
# Never call a number an industry standard unless the corpus carries it.

# 03 — generate a build spec (colours stay empty; they are a brand decision)
node .design-ops/design-systems/to-design-md.mjs --profile web --name "Product" -o DESIGN.md

Why you can trust the defaults

The kit's numbers are not taste. Each one comes from a corpus of design systems opened token by token, and every value carries its distribution and sample size.

—design systems measured
—pattern axes cross-cut
—agent procedures
—ready build specs

There is no standard button height. 40px is the most common — and across 77 systems it still turns up in barely a quarter of them. Spacing is no kinder: not one value survives all of them, 16px included.

That is why the kit ships distributions rather than rules, leaves anything unconfirmed standing as unverified, and has thrown out 24 of its own conclusions as the sample grew. Browse the evidence →

What this corpus holds itself to

Sources and versions are pinned

Every claim records which repository and which version or commit it was read from. When upstream moves, the drift gets caught instead of quietly absorbed.

Unknowns stay unknown

Phrases like "generally" and "most systems" are banned outright. Anything unconfirmed is marked unverified so the next person can pick it up.

Sample size travels with the claim

Not "16px is standard" but "10 of 68". Axes have different sample sizes, so quoting a conclusion means quoting that axis's count with it.

It overturns its own conclusions

24 of this corpus's own conclusions were discarded as the sample grew — and what was wrong, and why, stays on the record.

It will not pick your colors

Sizing, spacing and motion can be argued from distributions. A palette is a brand decision, so there is no recommended palette here.

No product data comes in

A specific product's tokens, event definitions and translated strings belong in that product's repository. Only shared assets live here.
