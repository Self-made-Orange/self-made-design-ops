Carbon Design System

IBM · enterprise · web

In one line

IBM's design system for enterprise products, designed on the premise of data-dense working screens.

Typography

The typeface is IBM Plex (Sans / Mono / Serif). The size scale is defined not as a list of values but as a recursive function.

@function get-type-size($step) {
  @if $step == 1 { @return 12px; }
  @return get-type-size($step - 1) + (math.floor(($step - 2) * 0.25) + 1) * 2;
}

The increment grows every four steps (+2 → +4 → +6 → +8 …), and 23 steps are generated.

12, 14, 16, 18, 20, 24, 28, 32, 36, 42, 48, 54, 60, 68, 76, 84, 92, 102, 112, 122, 132, 144, 156

Note: a comment in the source states the officially supported range as 12–92px (17 steps). The values past the 18th step are generated by the function but lie outside that range. The list above was recovered by running the function.

Source: @carbon/type@11.65.0 → scss/_scale.scss, scss/_font-family.scss

Three weights · eleven families (added 2026-08-18)

$font-weights: light 300 · regular 400 · semibold 600. There is no 700 (bold).

Eleven $font-families — sans · sans-condensed · serif · mono plus seven per-language faces (sans-arabic · sans-devanagari · sans-hebrew · sans-jp · sans-kr · sans-thai · sans-thai-looped). All are IBM Plex, and the fallback is the shared system-ui, -apple-system, BlinkMacSystemFont, '.SFNSText-Regular'. Only Thai gets two sets, looped and non-looped.

The raw palette — 13 families × 10 steps + hover twins

blue · cyan · gray · cool-gray · warm-gray · green · magenta · orange · purple · red · teal · yellow (12), each in 10 steps (10–100, by 10). There are three greys — neutral (gray), cool (cool-gray) and warm (warm-gray). black (black-100) and white (white-0) are separate.

Every swatch has a -hover twin.

$blue-60:       #0f62fe;
$blue-60-hover: #0050e6;
$white:         #ffffff;
$white-hover:   #e8e8e8;

124 non-hover variables (120 plus black-100 · white-0 · black · white) + 122 hover + the $colors map = 247 variables. Carbon is the only system in the corpus to put interaction state in the raw palette rather than the semantic layer. There are stretches where -70-hover is lighter than -60 (blue-70-hover: #0053ff), so it is not a simple shift in lightness.

There is no alpha family — every value is an opaque six-digit hex.

Four semantic themes — white / g10 / g90 / g100

All four themes are structurally identical at exactly 235 tokens. Between white and g100, 223 of the 235 differ. The 12 that hold the same value are backgroundBrand (#0f62fe) · textOnColor/iconOnColor (white) · overlay (rgba(0,0,0,0.6)) · the three warning colours (supportWarning · supportCautionMinor #f1c21b · supportCautionMajor #ff832b) · two aiAuraStart tokens · borderStrong02 · backgroundSelectedHover — the brand colour, the warning colours and the overlay are fixed regardless of mode.

Contextual layout tokens — size is inherited from the context

$layout-tokens: (
  size:    ( height: ( xs 24 · sm 32 · md 40 · lg 48 · xl 64 · 2xl 80 ) ),
  density: ( padding-inline: ( condensed $spacing-03 · normal $spacing-05 ) ),
);
@include layout.use('size', $default: 'md', $min: 'sm', $max: 'lg');

A component declares the size range it supports (min/max) and receives the actual size from the surrounding layout context — a text input's height is a single layout.size('height') reference. The same "context decides the value" family as Cloudscape's density modes, but Carbon alone puts all six size steps on the context axis.

Elsewhere

  • Modal widths are viewport percentages, not px — 48% / 60% / 84% by size and breakpoint (in contrast to the fixed-px camp of shadcn's 512px and Mantine's 440px; cross-referenced in patterns/modal.md)
  • Checkbox 16px (the convergent value), a 9×5px check mark, no notion of a touch target — the opposite pole from GOV.UK's 40px (a desktop-enterprise premise)
  • High-contrast support sits directly in the component source: border: 1px solid ButtonBorder (a forced-colors system colour keyword)

Tables (data-table) — five density steps, straight off the layout-token ladder

sizerow heightcell block padding
xs24px2 / 2px
sm32px7 / 6px
md40px7 / 6px
lg (default)48px ($spacing-09)$spacing-05 = 16 / 16px
xl64px16 / 16px
  • Five density steps, the most in the sample collected (Vuetify, Chakra, PrimeVue, Semi and Naive have three; Cloudscape two). The values match the size.height ladder in utilities/_layout.scss exactly (xs 24 / sm 32 / md 40 / lg 48 / xl 64 / 2xl 80) — the table has no dimensional system of its own and uses the shared contextual layout tokens.
  • The cell block padding is asymmetric at 7 / 6px (sm and md). The 13px total plus the line height produces 32 and 40px, and the values fall off any multiple of 4.
  • The cell inline padding is fixed at $spacing-05 (16px) across every step — the Cloudscape and Semi camp, where density reduces only the vertical.
  • There is a 1px border both above and below, but the top one is $layer (the background colour) — on hover and selection only the top border takes a colour, so the layout does not shift.
  • The sticky header switches to display: flex plus position: sticky plus z-index: 1 plus will-change: transform.
  • The sort icon is 20px and sits at opacity: 0 while unsorted, going to 1 when sorting is active. Descending is a transform: rotate(180deg) with a transition — the code-layer implementation of the three-state rule (unsorted → up → down) stated in the documentation layer. The sorted column's header background changes to $data-table-column-hover.
  • Zebra striping (--zebra) is nth-child(odd), and its combinations with selection and hover are enumerated across eight separate selectors.

  • Expanded 256 / collapsed 48 is exactly the same as shadcn/ui. Two unrelated systems arrived at the same pair of values.
  • The active marker is a 3px vertical bar on the left — a fourth approach alongside the underline, pill and background, and the case in the sample of a vertical indicator in a side navigation.
  • Inactive tabs carry a 2px underline too (only the colour differs, $border-subtle) — the thickness does not change on becoming active. The same idea as Semi keeping its hover underline at the same weight.
  • Tabs and tags inherit their size from the context via layout.use('size', …) (see "contextual layout tokens" above) — the same mechanism as the table.

  • The toast width is responsive (288 → 352px). The only case in the sample collected of changing a toast's width by breakpoint — the rest are fixed (Sonner 356 · PrimeVue 352 · Ant and Grommet 384 · Naive 365) or have no width (Semi).
  • The 6px left accent border is the second thickest in the sample after Vuetify's 8px (EUI 3 · Cloudscape 2). It halves to 3px in the low-contrast variant alone — as the background lightens, the accent line is taken thinner too.
  • The close button is 48×48px — a case of applying a touch-target spec to dismissing a notification, taking up a sixth of the toast's 288px width.
  • The tag overrides the shared height ladder to 18/18/24/32 with layout.redefine-tokens — a structure in which the same step names hold different values per component.

Characteristic decisions

  • There are fine 2 and 4px units at the bottom of the spacing scale. A base-8 system that nonetheless provides 2px and 4px as $spacing-01/02.
  • The type scale is a function. The values are generated by an increment rule rather than picked by hand — the advantage being that no arbitrary judgement enters when the scale is extended.
  • The top of the spacing scale jumps to 160px. 96 → 160 is a larger leap than the other steps (1.3–1.5×).
  • Hover colours ship as pairs in the raw palette (2026-08-18). Each of the 122 swatches has a -hover twin ($blue-60 / $blue-60-hover). The corpus majority builds interaction state at the semantic layer; Carbon starts out with state already present at the raw layer.
  • There are three grey ramps — neutral gray, cool cool-gray and warm warm-gray. Ten steps each, so the greys alone number 30.
  • Colour has a layer axis too. The 29 layer* tokens including layer01/02/03 build the same "context decides the surface colour" structure as the contextual layout tokens in spacing.
  • There is a colour family dedicated to generative AI — 21 ai* tokens (aura, border, popover shadow) and 21 chat*. Carbon is the system in the sample that raised AI UI colours into a token family.
  • The weight ceiling is 600 (light 300 · regular 400 · semibold 600). There is no 700 — the same as Primer.
  • Tracking is loosened on small text (0.32px at 12px → 0 from 16px up). The opposite direction from Cloudscape and Polaris, which tighten into the negative as the size grows.

Accessibility

Source: https://carbondesignsystem.com/guidelines/accessibility/overview/

  • The standard invoked: "Carbon components follow the IBM Accessibility Checklist which is based on WCAG AA, Section 508, and European standards." → Rather than declaring a WCAG level directly, it goes by way of the IBM Accessibility Checklist, and that checklist grounds itself in WCAG AA, Section 508 and the European standards.
  • Only contrast names a version: "Carbon color themes strive to comply with the WCAG 2.1 AA guidelines for contrast."
  • Three lines of intent: an experience of equal quality for every user · adaptation to the user and the situation · patterns that are perceivable, operable and understandable.
  • The recommended tools are listed in the documentation: the IBM Equal Access Toolkit · the High Contrast Chrome plugin · the Stark Figma plugin · a colour contrast tool. (A rare case of officially recommending a contrast-checking plugin for Figma.)
