Tailwind CSS

Tailwind Labs · framework · web

In one line

A utility-class CSS framework. From v4 on, the entire theme is one file of CSS variables (theme.css), and it ships no components — only the token layer.

A note on classification. Every other entry in this corpus is a design system a company built for its own product. Tailwind has no product; it is a framework, so it is marked domain: framework (see SCHEMA.md). The same applies to shadcn/ui, Mantine and Radix Themes below.

Tokens

Spacing — the only system in the sample that does not enumerate a scale

--spacing: 0.25rem;   /* 4px. That is all of it */

There are no steps. p-3 is calc(var(--spacing) * 3) = 12px, generated by multiplication. Not only integers work: p-1.5 (6px) and p-2.5 (10px) are valid too.

approachsystems
enumerate the stepseverything else in the sample
one base plus multiplicationTailwind v4

This differs from Ant Design deriving its scale from sizeUnit and sizeStep — Ant emits the derived results as a finite list of tokens, whereas Tailwind never produces the list at all.

Practical consequence: there is no scale to carry into a design tool. To export to Figma Variables you must pick and enumerate the steps you intend to use.

Three symmetric steps on both sides of 0, unlike Backpack and Seed Design, which offer only negatives (patterns/typography.md).

Nine weights: 100 · 200 · 300 · 400 · 500 · 600 · 700 · 800 · 900 — --font-weight-thin through --font-weight-black, every hundred.

Colour — 286 of them, 26 hues × 11 steps

family
achromaticgray · slate · zinc · neutral · stone · mauve · mist · olive · taupe
chromaticred · orange · amber · yellow · lime · green · emerald · teal · cyan · sky · blue · indigo · violet · purple · fuchsia · pink · rose

The steps are 50 · 100 · 200 … 900 · 950 — 11 of them, identical across all 26 hues. Adding --color-black and --color-white brings the total to 288.

mauve · mist · olive · taupe sit in the achromatic family. Other systems in the sample keep one or two grey families. Tailwind has nine.

There is no semantic layer. There are no role tokens like text-primary or surface, only raw colours. The role layer is the user's to build — which is exactly what shadcn/ui does.

Breakpoints and containers are separate families. The xl breakpoint (80rem) and the 7xl container (80rem) hold the same value under different names.

--perspective-* is a token. Tailwind is the only system in the sample that puts 3D perspective distance into named steps.

The global transition default is a token too — 150ms / cubic-bezier(0.4, 0, 0.2, 1).

Components

None. Only utility classes and tokens.

Characteristic decisions

  • It does not enumerate spacing. Everything is generated by multiplying the single --spacing: 0.25rem. Unique among the 34 samples.
  • There is no semantic colour layer. Only 286 raw colours. Where other systems keep a two-tier scale/ + semantic/ structure, Tailwind keeps one tier.
  • There are nine achromatic families, including mauve · mist · olive · taupe.
  • Line height is attached to the size token — --text-sm--line-height, using a double hyphen to express a token's sub-property. Tailwind is the only place in the sample using this notation.
  • rem breakpoints. Most systems use px. Here the breakpoints respond to the user's font-size setting.
  • Families like --perspective-* and --text-shadow-* are tokens. The tokenised surface is wider than in other systems.
  • There is no runtime multiplier variable. It does not use the calc(var(--scale) * N) approach of Mantine, Radix Themes and Vapor UI. Changing --spacing itself moves all spacing with it, so the same adjustment is possible in effect.

Accessibility

The files state no accessibility target at the token or CSS level. With no components, ARIA and focus management are out of scope.
