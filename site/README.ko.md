# site/ — GitHub Pages 사이트

공개 주소: **https://keepyaoung.github.io/self-made-design-ops/**

코퍼스를 **찾아볼 수 있게** 만든 한 장짜리 정적 페이지입니다. 새 사실을 담지
않습니다 — 전부 저장소 문서로 이어지는 색인이고, 값의 근거는 링크된 문서에
있습니다.

**사이트 문안은 영어입니다.** 링크 대상 문서는 한국어이므로, 그 사실을 페이지
안에 명시해 뒀습니다. 데이터에서 오는 한국어 값(`미확인`, `문서` 같은
`tokens_format` 표기)은 `build.mjs`의 `TOKEN_LABEL_EN` 표에 있는 것만 영어 라벨을
함께 실어 보내고 **원문은 툴팁으로 남깁니다**. 표에 없는 값은 임의로 번역하지
않고 원문 그대로 나갑니다.

## 갱신

코퍼스를 고쳤으면 재생성하고 함께 커밋합니다:

```bash
node design-systems/build-data.mjs   # systems/*.md frontmatter → data/systems.json
node site/build.mjs                  # → docs/data/corpus.json
node site/check-headlines.mjs        # 축 결론이 아직 유효한가?
```

잊어버린 경우 `.github/workflows/site.yml`이 PR에서 실패시킵니다.

## 숫자를 다루는 규칙

- **시스템 목록·집계**는 `design-systems/data/systems.json`에서 옵니다.
  사이트가 따로 세지 않습니다.
- **축별 표본 수**는 각 `patterns/*.md`의 `## N표본 재종합` 제목에서 읽습니다.
  문서 앞부분의 요약이 아니라 재종합 절이 우선이라는 코퍼스 규칙
  (`agents/design-review.md`)을 생성기가 그대로 따릅니다. 제목이 없으면
  추정하지 않고 **빌드를 실패시킵니다.**
- **한 줄 결론**(`AXES[].headline`)만 사람이 씁니다. `agents/design-review.md`의
  "핵심 기준" 표에서 옮긴 요약이며, 판정 기준은 원문입니다.
- **그 결론은 믿는 게 아니라 검사합니다** — `site/check-headlines.mjs`가 헤드라인이
  말하는 숫자를 원본 문서의 표에서 다시 세고, 인용한 값이 아직 본문에 있는지 확인합니다.
  CI에서 `--strict`로 돕니다. 산문을 읽고 판정하지는 **않습니다**. 기계로 확인할 것이
  없는 주장은 조용히 통과시키지 않고 **미검사**로 보고하므로, 검증 불가능한 결론을 가진
  축이 계속 눈에 남습니다. 이게 필요한 이유는 같은 실패가 이미 세 번 났기 때문입니다 —
  표가 보강되고 한참 아래 요약문이 그대로 남는 경로 (typography 13 → 17,
  `scales.md` 6 → 8, 둘 다 2026-08-19에 수작업으로 발견 · `motion.md`의 reduced-motion 표가
  9개 층 17개 시스템이 됐는데 세 문장이 여전히 6개 층 13개 시스템이라고 말한 건
  2026-08-23에 발견).

## 테마 — 라이트 기본 + 선택적 다크

> **2026-08-22(12차)에 갱신.** 다크 테마가 헤더의 명시적 토글로 돌아왔습니다.
> **기본은 여전히 라이트**이고, 아래 메모는 페이지가 라이트 전용으로 돌던 날의 기록으로
> 남습니다. 두 절 아래의 팔레트 설명은 지금 토글이 되살리는 다크 세트를 그대로 설명합니다.
>
> 저장 상태는 셋이고, 서로 다른 것입니다 — `'light'`, `'dark'`, 그리고 **아무것도 없음**.
> 없음은 *OS를 따른다*는 뜻이고, 방문 중간에 OS가 바뀌는 것까지 포함합니다(페이지가 그
> 변화를 듣습니다). 첫 클릭이 명시적 선택을 기록하고, 그때부터 페이지는 OS를 따르지 않습니다
> — 인페이지 스위치가 시스템 스위치를 이기는 게 보통 기대되는 동작이기 때문입니다. 이 선택은
> 각 `<head>`의 네 줄짜리 인라인 스크립트가 **첫 페인트 전에** 읽습니다. `assets/site.js`는
> defer이고, defer 스크립트로는 반대 테마가 한 번 번쩍입니다.

> **다크 테마와 토글을 제거했습니다 (2026-08-21).** 페이지는 라이트 전용이었습니다 —
> `:root` 하나가 팔레트를 들고, `color-scheme: light`, `[data-theme]` 블록 없음,
> 첫 페인트 전 스크립트 없음, `localStorage` 사용 없음. 예전에 테마를 뒤집던 세 조건을
> 헤드리스로 전부 확인했습니다 — 새 방문, `theme: 'dark'`가 저장돼 있던 방문자,
> OS가 다크를 선호하는 경우 — 전부 `rgb(250,249,247)`로 떨어집니다.
>
> 같이 빠진 것 둘. **히어로 사진**은 다크 전용 에셋(라이트에선 숨김)이었으므로
> `.hero-media` 요소·CSS·드리프트 애니메이션이 함께 빠지고 히어로는 따뜻한 CSS 블룸만
> 남습니다. `docs/assets/hero-bg.jpg`와 `fetch-hero` 워크플로는 지우지 않았지만 이제
> **참조되지 않습니다**. **푸터는 계속 다크 슬래브**입니다 — 이건 테마가 아니라 페이지를
> 코퍼스 정체성으로 닫는 장치이고, 여전히 자기 스코프에서 팔레트를 재정의합니다.
>
> 아래 절들은 테마를 어떻게 만들었고 값이 왜 그런지에 대한 기록으로 남겨 둡니다.

## 테마 — 만든 과정 (라이트 기본 + 다크 토글)

  꼬리 헤어라인. 번호만 오렌지.

전부 저자 결정(A)이며 코퍼스 값이 아닙니다.

### 2차 (사용자가 실제 sanity 스크린샷 제공) — "너무 AI 같다" 교정

사용자가 sanity.io 홈 스크린샷 2장을 줬습니다(라이브는 여전히 프록시 차단).
관찰 → 기획 → 적용:

- **관찰 1 — 포인트컬러를 전면(full-bleed) 블록으로 빡빡하게 쓴다.** Sanity는
  솔리드 오렌지 밴드 안에 다크 코드 창을 넣는다.
  → **적용**: "Hand it to an agent"를 히어로 밖으로 빼 **전폭 솔리드 오렌지
  섹션**으로. 그 위에 **다크 터미널 창**(타이틀바 3점 + `agent-rules` + 스니펫)을
  얹고, 헤딩은 오렌지 위 검정 잉크, 버튼은 검정. 그리드 프레임을 깨고 100vw.
- **관찰 2 — 카드가 단순 박스가 아니라 개성 있는 UI 패널이다**(코드 에디터·
  스튜디오 폼·히스토리·릴리스 카드).
  → **적용**: 패턴 축 카드를 **큰 실측 숫자 카드**로. 각 카드가 틸 색 대형
  숫자(77·68·79…)+`SAMPLES`로 시작 — 우리 정체성(측정)이 카드의 개성이 되게.
  (116개 시스템 인덱스 카드는 브라우징 기능이라 UI 목업화하지 않고 데이터 칩 유지.)
- **관찰 3 — 히어로가 버튼 쌍으로 행동을 유도한다.**
  → **적용**: 히어로에 **오렌지 채움 "Browse 116 systems →" + 아웃라인
  "Agent guides"** 버튼 행 추가.

버튼 프라이머리는 딥오렌지(#c2410c) 흰 라벨(AA), 오렌지 밴드 위 버튼은 검정
바탕 흰 라벨. 스크린샷 기반이라 실제 sanity 와 세부는 다를 수 있습니다.

### 3차 — 히어로 배경 + 터미널 타이핑 애니메이션

- **히어로 분위기 배경 (실사진)** — 처음엔 CSS 그라디언트였는데, 사용자가
  **실제 사진**을 원했습니다. 이 컨테이너는 `images.unsplash.com`이 프록시에
  403으로 막히지만 **GitHub Actions 러너는 인터넷이 열려 있어**, `fetch-hero.yml`
  (`workflow_dispatch`, `url` 입력)이 러너에서 이미지를 받아 저장소에 커밋합니다.
  받은 사진(Unsplash `photo-1541701494587-cb58502866ab`, 잉크 확산, **Unsplash
  License** 무료)을 `docs/assets/hero-bg.jpg`로 자기 호스팅하고, **블러 9px +
  밝기 0.72**로 다듬었습니다(PIL). 히어로에서는 오렌지 쪽이 오른쪽에 오도록
  배치하고, 왼쪽(텍스트)·하단은 어두운 스크림으로 덮어 가독성을 지킵니다.
  30s 아주 느린 스케일 드리프트(reduced-motion에서 정지).
  **이미지 교체는** `fetch-hero` 워크플로를 다른 `url`로 다시 돌리면 됩니다.
- **스크롤 시 흰색 내비** — 히어로 위에선 헤더가 투명(위쪽 옅은 다크 스크림으로
  라이트 라벨 가독성 확보)이고, 히어로를 지나 **섹션 2부터 솔리드 흰색 바로
  전환**되며 텍스트가 다크로 바뀝니다(`header.site.scrolled`, `scroll` 리스너
  rAF 스로틀, 임계값 = 히어로 높이 − 64). 전환은 배경·보더·그림자 트랜지션.
  **버그 하나 같이 잡음**: 앞서 그리드 룰(`main, header.site, footer.site
  { position: relative }`)이 헤더의 `sticky`를 덮어써 헤더가 스크롤에 딸려
  올라가던 것을, 그 룰에서 헤더를 빼 `sticky`를 복구했습니다.
- **터미널 타이핑** — 섹션 2 코드창이 스크롤로 들어오면 한 글자씩 타이핑됩니다
  (`IntersectionObserver`, 1회). 줄이 끝나면 `git clone` 키워드 하이라이트를
  입히고, 오렌지 블링킹 커서가 붙습니다. **`prefers-reduced-motion`이면 타이핑
  없이 완성본을 즉시** 보여줍니다. 타이핑 중 Copy를 눌러도 `pre[data-full]`에
  전체 스니펫을 담아 둬 온전히 복사됩니다.

### 4차 — 버튼 pill 통일

인터랙티브 컨트롤을 **완전한 pill(`--r-full`)**로 통일했습니다(애매한 스쿼클
제거): 히어로 CTA(`.btn`)·Copy(`.copy`)·Reset(`.reset`)·GitHub(`.gh`)·검색
인풋(`#q`). 카드/패널 같은 **컨테이너는 그대로 스쿼클**(`--r-md`)로 둬 버튼과
구분합니다. 칩·수집 깊이·샘플 배지는 이미 pill이라 변화 없음.

> **2026-08-21에 뒤집혔습니다 — 컨트롤은 각지게(0).** 같은 여섯에
> `--r-control: 0px`를 물립니다 — 히어로 CTA·Copy·Reset·GitHub·테마 토글·검색 인풋.
> `tokens/scales.md`에 라운드 0 진영이 기록돼 있어 값 자체는 근거가 있고, 선택은
> 저자 판단(A)입니다. 인풋이 버튼과 계속 같은 모양이라 짝이 유지됩니다
> (`patterns/form.md`). **칩·배지 계열은 `--r-full` 유지** — 필터 칩이 `<button>`이긴
> 하나 비인터랙티브 배지(수집 깊이·샘플·태그)와 한 계열로 그려져 있어서, 필터만
> 각지게 하면 계열이 쪼개집니다. 컨테이너는 그대로입니다. 되돌리려면
> `--r-control` 하나만 바꾸면 됩니다.

배경 도트는 **`body` 자체의 `background-image`**(`background-attachment: fixed`)로
칠합니다. 이전엔 `body::before`에 `z-index: -1`을 줬는데, **불투명한 `html` 배경
뒤로 밀려 실제 페이지에서 도트가 보이지 않았습니다.** 배경을 body 위에 직접
얹어 그 함정을 없앴습니다. 격자 24px은 `tokens/scales.md` 간격 스케일의 한
단계이고, 히어로 상단의 옅은 액센트 글로우가 다크 캔버스를 살짝 띄웁니다.

### 5차 — Tailwind showcase 에디토리얼 프레이밍

`tailwindcss.com/showcase`의 **카드 섹션 + 배경 패턴(에디토리얼 프레이밍)**을
참고했습니다. 그 사이트도 이 컨테이너에선 프록시에 막혀 있어, **Actions 러너에서
`peek-url` 워크플로**(러너는 인터넷이 열림)로 실제 마크업을 받아 구조를 읽고
옮겼습니다 — 이미지 추측이 아니라 실제 클래스 트리 기준.

- **카드 = 프레임된 셀**(부유하는 박스 아님). 각 카드가 얇은 **세로 사이드 룰**
  (`border-inline`)을 지녀 페이지의 거터 격자와 호응하고, 그리드 상단에 가로 레일
  (`border-top`)을 둘러 장부(ledger)처럼 닫습니다. 카드 배경·둥근 모서리·박스
  테두리를 걷어내 "AI 카드" 느낌을 줄였습니다. 열 간격은 0으로 두고 인접 카드
  룰을 `margin-inline: -1px`로 겹쳐 한 획으로 만듭니다.
- **호버는 색만**(`transition: background-color`, 리프트 없음) — showcase의
  `group hover:bg` + `transition-colors`를 그대로. 링크 카드는 사이드 룰이 살짝
  액센트로 물들고, 시스템 카드(`div`)는 옅은 틴트만.
- **시스템 카드 전체가 클릭됩니다** (2026-08-21 추가). 축·가이드·프로필 카드는 각각
  `<a>` 하나인데, 시스템 카드는 링크가 3개(코퍼스 문서·공식 사이트·소스)라 `<a>`
  중첩이 불가합니다 — 그래서 `div`를 유지하고 코퍼스 문서 링크를
  `a.entry::after { position: absolute; inset: 0 }`로 카드 전체에 펼칩니다
  (카드는 `position: relative`). 나머지 두 링크는 `z-index: 1`로 올려 각자 클릭을
  받습니다. 헤드리스로 검증 — 카드 빈 곳 클릭은 코퍼스 문서로, "Official" 클릭은
  해당 시스템 사이트로 갑니다.
- **카드 4종의 호버가 하나로 통일됐습니다** (2026-08-21). 클릭 수정 뒤 감사해 보니
  시스템 카드만 전 축에서 어긋나 있었습니다 — 워시가 약하고(0.024 vs 0.035),
  사이드 룰에 액센트 틴트가 없고, 호버 화살표도 없었습니다. 규칙을 `a.card`에서
  `.card`로 올려 축·가이드·프로필·시스템이 동일하게 동작합니다. 시스템 카드는
  우상단을 수집 깊이 배지가 차지하므로 화살표만 우하단으로 내렸고,
  `pointer-events: none`이라 펼친 링크를 가로채지 않습니다.
- **호버 워시를 테마 토큰(`--card-hover`)으로 뺐습니다.** 이전엔
  `rgba(255,255,255,0.035)` 고정이었는데 **흰색 오버레이**라 라이트 캔버스(`#faf9f7`)
  위에서 거의 보이지 않았습니다 — 그리고 라이트가 기본 테마입니다. 지금은 라이트에
  잉크(`rgba(20,18,15,0.045)`), 다크에 화이트라 양쪽 다 읽힙니다.
- **거터 대각 해치** — `.grid-lines::before/::after`가 읽기 열 바깥 좌우 거터를
  아주 옅은 45° 반복 스트라이프로 채워, 본문 열이 **프레임된 편집 지면**처럼
  읽힙니다(showcase의 사이드 거터 모티프). 뷰포트 가장자리로 갈수록 mask로
  페이드. 모바일(≤640px)에선 `.grid-lines`와 함께 사라집니다.

### 6차 — 라이트 테마 토글

**다크는 그대로 기본**이고, 라이트를 **옵트인 토글**로 추가했습니다(헤더 GitHub
버튼 왼쪽, `.gh`와 같은 pill). 선택은 `localStorage`에 저장하되 **저장하는 값은
`'light'` 하나뿐**이라, 스토리지를 비우면 다크로 돌아옵니다. `<head>`의 짧은
인라인 스크립트가 **첫 페인트 전에** 저장된 선택을 적용해 테마가 번쩍이지
않습니다.

라이트 팔레트는 다크와 같은 규율로 **전부 WCAG 계산**했습니다(캔버스 `#faf9f7`):
본문 16.8:1 · muted 6.5:1 · dim 4.9:1 · 링크 4.9:1 · 틸 5.2:1 · rank-b 4.9:1 ·
rank-c 5.7:1 · unverified 앰버 4.6:1.

- **밝은 프라이머리 `#f97316`는 라이트에서 2.7:1**이라 텍스트로 못 씁니다. 그래서
  **채움(fill)·도트·rank-a는 밝은 오렌지 그대로**, **텍스트만 깊은 `#c2410c`**로
  갈라놨습니다.
- 링크 색은 `--link` 토큰을 새로 두고 기본 규칙을 `a { color: var(--link) }`로
  바꿨습니다. 처음엔 `[data-theme="light"] a { … }`로 덮었는데, 그 선택자가
  `.brand`·`.gh`·`.btn-primary`보다 **우선순위가 높아** 로고와 GitHub 버튼이
  주황으로 물들고 **CTA가 주황 배경 위 주황 글씨(라벨 안 보임)**가 됐습니다.
  토큰으로 내리니 클래스 규칙이 정상적으로 이깁니다.
- 히어로 사진은 다크 전용 에셋이라 라이트에서는 숨기고 **따뜻한 그라데이션 워시**로
  대체합니다. 코드 패널은 두 테마 모두 **다크 유지**(문서 관례)하되 라이트에서는
  테두리를 어둡게 해 캔버스 위에 떠 보이지 않게 했습니다. 거터 대각 해치도
  라이트용으로 잉크를 반전했습니다.

헤드리스 브라우저로 **동작까지 검증**했습니다 — 기본 다크 → 클릭 시 라이트 저장 →
새로고침 후 유지 → 다시 클릭 시 다크 복귀 및 스토리지 삭제, 그리고 두 테마의
brand/GitHub/CTA/링크 계산색 확인.

### 7차 — 라이트를 기본으로 반전 + 다크 푸터

**기본 테마를 라이트로 뒤집었습니다.** 6차에서 라이트는 옵트인이었는데, 이제
`:root`가 라이트 팔레트를 들고 **`[data-theme="dark"]`가 옵트인**입니다. 저장하는
값도 `'dark'` 하나뿐이라 스토리지를 비우면 라이트로 돌아옵니다. 토글 아이콘은
"바꿔 갈 테마"를 보여주므로 라이트에서 달, 다크에서 해입니다.

반전하면서 **테마별 중복 규칙을 토큰으로 걷어냈습니다.** 세 토큰을 새로 뒀습니다:

- `--accent-text` — 액센트를 **텍스트로 쓸 때**의 색. 라이트 `#c2410c`(4.9:1) /
  다크 `#f97316`. 이전엔 `[data-theme="light"]`로 5개 규칙을 개별 오버라이드했는데
  토큰 하나로 전부 사라졌습니다. 채움·도트·rank-a는 여전히 밝은 `--accent`.
- `--hatch` — 거터 대각 해치 잉크
- `--hero-glow` — 헤드라인 뒤 웜 블룸

**구조적 차이만** `[data-theme="dark"]`에 남겼습니다 — 히어로 사진(다크 전용
에셋), 히어로/헤더 스크림, 코드 패널 테두리. 결과적으로 테마 오버라이드가
9개 규칙에서 4개로 줄었습니다.

**반전 과정에서 잡은 버그** — 항상 다크인 표면이 테마 토큰을 상속하고 있었습니다.
라이트에서 터미널 창(오렌지 블록 위)의 제목 표시줄 경계선이 `var(--border)`라
거의 흰 선으로 그어지고, `.tname`이 `var(--text-dim)`(#726c62)이라 다크 바 위에서
2.2:1까지 떨어졌으며, `git clone` 키워드가 `--accent-fg`를 타고 `#c2410c`로 어두워져
검은 배경에 묻혔습니다. 터미널·코드 패널은 **두 테마 모두 다크**이므로 해당
값들을 고정색으로 못박았습니다(키워드 `#ffa257` — 9.8:1).

**푸터는 두 테마 모두 다크 슬래브**입니다. 페이지가 코퍼스 자신의 정체성으로
닫히게 하려는 것으로, 서술자마다 색을 박는 대신 **푸터 스코프에서 팔레트 토큰을
재정의**해 내부 링크·코드·칩이 알아서 올바른 다크 값을 상속합니다. `#0d1117` 기준
본문 6.5:1 · 제목 16.0:1 · 링크 9.5:1 · dim 5.1:1 (dim은 다크 세트의 `#6e7681`이
4.1:1로 AA에 미달해 `#7d8590`으로 올렸습니다).

푸터에 **운영 주체(StudioSMO)** 표기를 추가했습니다. 저장소에
`LICENSE` 파일이 없어 **특정 라이선스명은 적지 않았고**, "오픈 소스 + 공개 저장소

### 15차 — 히어로 모션, 그리고 사이트가 자기 DESIGN.md를 갖다 (2026-08-22)

**히어로 뒤로 24px 도트 격자가 흐릅니다.** 데스크톱 폭에서 히어로 오른쪽 절반이 비어 있어서
모션은 거기 삽니다. 격자 단위는 지어낸 게 아닙니다 — 24px는 **29개 중 27개 시스템**의 간격
단계입니다(`tokens/scales.md`). 배경이 코퍼스가 이미 갖고 있는 값으로 지어진 겁니다. 흐르는
속도 24s linear는 저자 값(A)입니다. 코퍼스에 기댈 앰비언트 루프 지속이 없고,
`patterns/motion.md`에서 가장 긴 값이 Codex의 2000ms인데 성격이 다릅니다.

정확히 한 칸을 이동하고 패턴이 24px마다 반복되므로 페이드나 리셋 없이 이음매가 없고, 레이어를
-48px 안쪽으로 밀어 움직이는 가장자리가 상자 안으로 들어오지 않습니다. 방사형 마스크가 읽는
열에서 격자를 걷어냅니다.

눈대중 말고 잰 것 둘:

- **최악의 본문 대비** — 글자가 도트 한가운데 얹힌다고 가정한 값입니다. 마스크가 텍스트 영역의
  도트를 아예 지우므로 실제보다 엄한 조건입니다. 라이트 **5.64:1**, 다크 **6.01:1** (맨
  캔버스에서는 6.81 / 7.57). 둘 다 AA 위입니다.
- **reduced-motion 처방이 틀려 있었습니다.** 전역 규칙이 반복 횟수를 고정하지 않고
  `animation-duration: .01ms`만 걸고 있었습니다. *유한* 애니메이션에는 "즉시"로 읽히지만
  **무한** 애니메이션은 멈추는 게 아니라 초당 천 번 도는 겁니다. 이제 횟수도 고정하고 히어로
  격자는 아예 세웁니다. `reducedMotion: 'reduce'`로 확인 — 도는 애니메이션 0개.

### 14차 — CTA를 더 밝게 (2026-08-22)

소유자가 오렌지 CTA의 **채도와 명도를 더 올려 달라**고 했습니다. 그런데 흰 라벨을 유지한 채로
둘 다 올리는 건 사실상 불가능합니다 — 흰색 대 현재 `#c2410c`가 5.18:1이고, `#d44a05`에서
이미 AA 아래로 떨어집니다. **지금보다 명도 두 칸 위**입니다. "더 밝다"고 읽힐 만한 오렌지는
전부 흰 라벨로는 실패합니다.

근사 블랙 라벨을 두 패스에 걸쳐 시도했지만(`#ff8000` L50 → `#ff8f1a` L55) 소유자가 원치
않았습니다. **CTA는 소유자가 고른 `#ff5926` + 흰 라벨**이고, 그대로 나갑니다.

| | 이전 | 이후 |
|---|---|---|
| 채움 | `#c2410c` · H17 S88 L40 | **`#ff5926`** · H14 S100 L57 |
| 라벨 | `#ffffff` · 5.18:1 | `#ffffff` · **3.13:1** |
| 호버 | `#a83809` | `#f04a15` · 3.69:1 |
| 테두리 | (채움과 동일) | `#e8481a` · 라이트 캔버스 대비 3.71:1 |

**3.13:1은 AA 하한 4.5:1 아래**이고, 라벨이 15px/600이라 큰 글자(18.66px 볼드 또는 24px)에도
해당하지 않아 3:1 완화도 못 받습니다. 덮지 않고 적어 둡니다 — **이 페이지에서 실측 대비를
룩앤필과 맞바꾼 유일한 값**이고, 소유자의 의도된 브랜드 결정이며, `site.css`의 나머지는 전부
AA를 넘깁니다. 나중에 다시 볼 일이 있다면 싼 것부터: 라벨을 19px/700으로 올리거나(큰 글자로
3:1 통과), 채움을 `#e8481a`로 내리거나(흰색 3.91:1 — 그래도 모자람), 어두운 라벨로 되돌리기
(8.6:1).

어두운 라벨 두 패스가 밝혀낸 것 중 남는 건 이겁니다. `--accent`(`#f97316`)는 *채움과 점에만,
텍스트에는 절대*라고 주석에 적혀 있고, `--accent-text`(`#c2410c`)가 활자를 앉히는 깊은
쪽입니다. 버튼은 그 깊은 쪽을 **채움**으로 쓰고 있었고, 그래서 더 밝아질 수 없었습니다 —
이유 없이 텍스트 색의 제약을 지고 있었던 겁니다.

**테두리는 장식이 아닙니다.** 채워진 버튼의 경계는 WCAG 1.4.11에 따라 배경 대비 3:1을
넘겨야 하는데, `#ff5926`은 라이트 캔버스 대비 **2.97:1**입니다. 아슬하게 모자라고, 눈으로는
절대 안 잡히는 차이입니다. `--btn-line: #e8481a`가 대신 경계를 집니다 — 라이트에서
**3.71:1**, 다크에서 5.01:1. 밝은 배경 위의 채움을 밝히면 이 가장자리를 조용히 잃습니다.
이런 변경 뒤에 확인할 값이 하나라면 이겁니다.

`--btn`·`--btn-hover`·`--btn-text`·`--btn-line`은 이제 **테마 독립**입니다. 밝은 오렌지 위의
근사 블랙 라벨은 양쪽에서 똑같이 읽히니까요. 다크 블록이 `--btn`을 다시 선언하던 건 얻는 것
없이 중복이었습니다.

**헤드라인은 소유자가 끊은 자리에서 끊깁니다** — `Clone it once.<br>Make your DesignOps.` —
그리고 `.hero h1`에서 **`max-width: 17ch`를 뺐습니다**. 명시적 `<br>`이 있으면 ch 제한은
아무것도 제한하지 않고, 둘째 줄을 다시 접어서 의도한 두 줄을 세 줄로 만듭니다. 첫 시도에서
실제로 그렇게 됐습니다. 1920/1440/1200/940/768/560/390에서 세어봤고 **전부 두 줄**입니다.
320px에서는 세 줄이 되는데("Make your DesignOps."가 32px 하한으로 288px에 안 들어감) 가로
스크롤은 없습니다. 흔한 폰 하한보다 두 단계 아래라 허용되는 열화로 봅니다.

양쪽 테마 확인 — CTA와 Copy 모두 `rgb(255, 89, 38)`에 `rgb(255, 255, 255)` 라벨 3.13:1,
호버 3.69:1, 테두리는 라이트 캔버스 대비 3.71:1, 가로 스크롤 0, 페이지 에러 0.

### 13차 — 중립 블랙, 그리고 소유자가 쓴 헤드라인 (2026-08-22)

### 12차 — 껍데기 하나에 페이지 둘, 그리고 다크 토글 복귀 (2026-08-22)

시안 둘을 나란히 만들었습니다. **A**는 코퍼스를 조밀한 카탈로그로, **B**는 저장소를
**디자인옵스 스타터킷**으로 프레이밍하고 코퍼스를 그 근거로 두는 안. 소유자가 킷 프레이밍을
고른 뒤 핵심을 잡아냈습니다 — *"좌우 배치 아니었어?"* B가 슬그머니 248px 레일을 버리고 가운데
정렬 마케팅 페이지로 돌아가 있었고, 그래서 두 시안이 한 제품의 두 화면이 아니라 서로 다른 두
제품처럼 읽혔습니다.

그래서 껍데기를 상수로, 내용을 변수로 바꿨습니다.

- **`/` (`docs/index.html`) — 킷.** 히어로 → 세 명령 → 안에 든 것 → 9개 패턴 축 →
  기본값을 믿어도 되는 이유 → 원칙.
- **`/catalog.html` — 근거.** 같은 레일이 검색과 플랫폼/수집 깊이/도메인 패싯을 들고,
  오른쪽 열은 로고 열이 붙은 116행 표입니다.

공유되는 건 전부 페이지 밖 **`docs/assets/site.css`**와 **`docs/assets/site.js`**로
옮겼습니다. `docs/preview.html`과 `docs/preview-kit.html`은 삭제했습니다 — 시안이었고,
저장소에 남은 시안은 두 번째 진실 공급원이 됩니다.

**레일은 인벤토리에서 어긋날 수 없습니다.** 하위 항목이 `corpus.json`의 `kit` 그룹에서
생성되고, 그건 "안에 든 것" 목록이 읽는 바로 그 배열입니다. 킷에 파일이 하나 추가되면 둘 다에
나타나거나 둘 다에 안 나타납니다.

**다크 토글**은 위 테마 절에 적었습니다. 비용은 병합된 크롬에 맞춰 다크 팔레트를 다시 유도해야
했다는 것이고, 수치는 눈대중이 아니라 `#0d1117` 기준 WCAG 계산입니다 — 본문 16.0:1 ·
보조 6.5:1 · 흐린 5.1:1 · 링크 6.8:1 · 경고 9.7:1 · Copy 버튼 흰 라벨 5.2:1. 같이 라이트
세트도 다시 쟀는데 주석 하나가 **틀렸습니다** — `--text-mut`를 6.5:1이라고 적어 뒀지만 실제는
6.8:1. 그 자리에서 고쳤습니다.

**스크린샷이 잡은 결함 하나.** 620px 아래에서 헤더 행 — 브랜드·알약 둘·토글 — 이 더는 안
들어가고, **안 들어가는 flex 행은 문서를 넓힙니다**: 390px에서 인덱스 가로 스크롤 64px,
카탈로그 22px. 그 폭에서는 GitHub 알약을 숨깁니다 — 넷 중 다른 데 실려 있는 유일한 것이고
(레일과 푸터가 둘 다 링크합니다), 테마 토글은 어디에도 실려 있지 않습니다. 더 작은 것 하나 —
헤더의 카운트 알약이 `Catalog116`으로 붙어 나왔습니다. `.ctrl`은 inline-flex 상자인데 카운트
span이 자기 간격을 안 갖고 있었습니다.

두 페이지 × 양쪽 테마 × 1440/940/390에서 헤드리스 확인 — **가로 스크롤 0, 페이지 에러 0**,
킷 19행, 축 카드 9개, 카탈로그 116행, 필터 칩 17개, 채워지지 않은 `—` 자리표시자 없음,
페이지 간 이동 후에도 테마 유지, 양쪽 테마에서 호버 보임(`--hover`가 테마별 토큰이지
하드코딩된 흰 오버레이가 아닙니다 — 10차의 그 버그).

### 11차 — 로고를 하나도 안 갖고 로고 열 만들기 (2026-08-22)

수백 개 브랜드 아이콘을 어떻게 갖고 있나? 안 갖고 있습니다. getdesign.md 마크업을 러너에서
읽어 보니 **`github.com/<org>.png`를 핫링크**하고 저장은 안 합니다. 자산이 아니라 핸들입니다.

`docs/preview.html`도 같은 방식이고, 재료는 코퍼스에 이미 있습니다 — `repo`에서 org가 나오니
수집 단계 자체가 없습니다. **116개 중 101개가 핸들을 갖고, 고유 98개이며, 98개 전부 200으로
해결됩니다** (`check-avatars`, 2026-08-22).

- **정규식을 일부러 앵커하지 않았습니다.** `repo`에 산문이 섞인 항목이 있어서
  ("github.com/nordhealth/design-system — declared in the package") 앵커하면 Nord와 하나를
  놓칩니다.
- **repo 없으면 요청도 없습니다.** Apple·Google 플랫폼 킷, Toss, Gojek, Tokopedia는 모노그램을
  유지합니다 — 가리는 대신 사실을 드러내는 쪽입니다.
- **`referrerpolicy="no-referrer"`** — 방문자 페이지 URL이 GitHub으로 가지 않습니다.
- **핫링크 핸들도 고정 버전처럼 낡습니다** — org 이름이 바뀌면 아바타가 404가 되고 행은 조용히
  모노그램으로 떨어집니다. `check-avatars`가 매월 전수 확인하고 실패만 보고합니다
  (`check-sources`와 같은 모양).

**기록해 둘 버그.** 처음엔 프로브를 DOM 밖 `new Image()` + `loading="lazy"`로 만들었는데
**요청이 한 건도 안 나갔습니다.** 문서 밖의 lazy 이미지는 기준 삼을 뷰포트가 없어서 브라우저가
영원히 미룹니다. 지금은 `<img>`를 바로 DOM에 넣고 모노그램 위에 투명하게 올린 뒤 `load`에서
드러내고, `error`면 스스로 제거합니다. 수정 후 실측: 첫 페인트에 28건, 나머지는 정상 지연.

### 10차 — 시스템 브라우저를 카드 그리드에서 카탈로그로 (2026-08-22)

116개를 에디토리얼 카드로 두니 두 시스템을 비교하려면 스크롤이 너무 길었습니다. 이제
**앱 셸**입니다 — 248px 고정 필터 레일 옆에 밀집된 호버 인덱스, 시스템당 한 행, 컬럼 룰러,
카드 크롬 없음.

**getdesign.md를 참고**했습니다. 같은 문제(수백 개를 스캔 가능하게 유지)를 푸는 사이트입니다.
이 컨테이너에서는 프록시에 막혀 있어 `peek-url` 워크플로로 Actions 러너에서 읽었습니다.
가져온 것은 **레이아웃 관습**입니다 — 고정 레일 + 밀집 행 인덱스, 그 위의 컬럼 룰러, 행
호버만을 어포던스로 쓰는 것, 작은 모노 메타 컬럼. 콘텐츠·타입 스케일·팔레트·카피는 이
페이지 것입니다. 다른 레이아웃 결정과 같이 등급 A.

그 긴 페이지를 읽으려고 `peek-url`에 `lines` 입력을 넣었습니다 — 잡 로그는 꼬리부터만
읽히는데 목록 행 수백 개가 헤더와 히어로를 묻어버렸습니다.

| | 이전 | 이후 |
|---|---|---|
| 레이아웃 | 3열 카드 그리드 | 248px 고정 레일 + 행 인덱스 |
| 항목당 | 제목·조직 줄·태그 행·링크 3개 카드 | 한 행: 이름 · 조직 · 도메인 · 수집 깊이 · 플랫폼 · 링크 |
| 필터 | 그리드 위에 쌓인 칩 행 | 레일 안의 세로 패싯 그룹, 각각 모노 라벨 |
| 항목 링크 | 카드 전체에 펼침 | 행 전체에 펼침 (같은 `::after` 방식) |

남겨 둘 세부:

- **이름은 잘리고 마커는 안 잘립니다.** `Figma`·`N open`은 알약이 아니라 맨 모노 주석으로
  이름 옆에 붙고, 이름이 `flex: 0 1 auto`라 마커를 밀지 않고 자기가 말줄임됩니다.
  1280px에서 116개 중 12개가 잘리며, 전부 링크 `title`에 전체 이름 + 검증일 + 토큰 형식이
  들어 있습니다.
- **플랫폼은 주 값만 보이고 나머지는 개수로** — `web +2`, 전체는 호버로. 코퍼스가 `platform`
  배열의 첫 값으로 집계하므로(`platforms.md`) 데이터와 맞고, 세 값짜리 목록이 옆 컬럼을
  침범하지 않습니다. 고치기 전 Fluent 2가 정확히 그러고 있었습니다.
- **컬럼 룰러는 760px 아래에서 사라지고** 행이 쌓입니다. 레일은 900px 아래에서 고정 해제.

### 9차 — 히어로가 인벤토리 대신 발견을 앞세우게 (2026-08-21)

히어로가 스펙 시트처럼 읽혔습니다. 아이브로우("reading the docs was never enough")와
리드 첫 문장("A pile of design-system docs to read was never enough")이 같은 말을 두 번
했고, 헤드라인("116 design systems, measured and ready to build with")은 재고를 설명할 뿐
읽는 사람이 왜 신경 써야 하는지를 주지 않았습니다.

지금은 코퍼스 자신의 발견으로 엽니다 — **"There is no standard button height."**
리드가 근거를 답니다(40px가 77표본 최빈인데도 채 4분의 1이 안 되고, 스페이싱은 16px
포함 어떤 값도 전 표본을 살아남지 못함). 그다음에 이게 무엇인지로 넘어갑니다. 두 주장
모두 카피가 아니라 코퍼스 값입니다 — 버튼 수치는 `button.md` 재종합, 스페이싱은
`tokens/scales.md`의 "무결값이 사라졌다" 절.

**히어로의 숫자는 데이터에서 옵니다.** 버튼 주장 옆 표본 수는 Buttons 축에서
(`#hero-btn-samples`), CTA 라벨의 개수는 `d.count`에서(`#cta-count`) 읽습니다 — 타이핑한
숫자처럼 코퍼스와 어긋날 수 없습니다. 헤드라인 `max-width`는 15ch → 19ch로 넓혀,
한 문장이 좁은 기둥으로 쌓이지 않고 두 줄로 앉습니다.

**같이 잡은 버그:** `.btn`이 gap 있는 `inline-flex` 행이라, 개수를 맨 `<span>`으로 감싸니
그게 플렉스 아이템이 되어 "116" 양옆에 간격이 생겼습니다. 라벨을 다시 한 아이템으로
묶고 화살표만 분리했습니다.

### 8차 — 푸터를 일반적인 사이트 푸터로

7차까지 푸터 본문은 **제작자용 메모**였습니다 — 간격 스케일, 컨트롤 높이, 포커스
링 두께, 도트 격자 24px 같은 근거 등급 문단이 200단어 가까이 들어가 있었습니다.
**방문자가 푸터에서 찾는 것**(이게 뭔지 / 누가 운영하는지 / 소스는 어디인지 /
언어 / 알아야 할 단서)과 어긋났고, 같은 내용이 이 문서에 이미 더 자세히 있어
중복이었습니다. 사이트 스스로 내건 "이 페이지는 새 사실을 담지 않는 색인"이라는
원칙과도 맞지 않았습니다.

**표준 4컬럼 + 하단 바 구조로 교체**했습니다:

| 컬럼 | 내용 |
|------|------|
| 브랜드 | 🍊 로고 + 한 문장 소개 |
| Explore | 페이지 내 앵커 5개 (헤더 내비와 동일) |
| Corpus | 저장소 · 시스템 색인 · 구현 기본값(EN) · 에이전트 절차 · DESIGN.md 프로필 · 이 페이지 빌드 문서 |
| Languages | README 6개 언어판 |

하단 바에는 `© <연도> StudioSMO · Open source`와, 방문자가 실제로 알아야 할 단서
두 줄(**문서 본문은 한국어** / **목록·표본 수는 생성물이라 손으로 고치지 않는다**)만
남겼습니다. 근거 등급 문단은 통째로 빼고 Corpus 컬럼의 "How this page is built"
(`site/README.md`) 링크로 대체했습니다.

**같이 잡은 오류 두 건** — 둘 다 이 코퍼스가 금지하는 종류였습니다:

- **거짓 주장.** 푸터가 "Primer의 액센트 `#1f6feb`가 이 페이지의 유일한 코퍼스
  실측 색"이라고 적고 있었는데, `grep -c "1f6feb" docs/index.html` → **1**, 그
  한 번이 **그렇게 말하는 문장 자신**이었습니다. 스타일시트 어디에도 없는
  색입니다. 프라이머리를 오렌지로 바꾸기 전 문장만 남은 잔재라 삭제했습니다.
  하필 "근거 없는 값은 채우지 않는다"고 적힌 문단 안에 있었습니다.
- **깨진 문자열.** 마지막 줄이 `corpus.json — generated from … patterns/*.md
  재종합 절 제목`으로, 영어 페이지 끝에 한국어 조각이 붙어 디버그 출력처럼
  보였습니다. 출처인 `site/build.mjs`의 `generated_from`을 영어 문장으로
  고쳤고(`the "N표본 재종합" heading in patterns/*.md` — 실제 제목이 한국어라
  그 부분만 원문 유지), 푸터에는 **생성기 문자열을 그대로 찍지 않고** 하단 바에
  사람이 읽는 문장으로 옮겼습니다.

저작권 연도는 **런타임에 찍습니다**(`new Date().getFullYear()`). 정적 페이지에
연도를 박아 두면 조용히 낡습니다 — 드리프트를 잡자는 저장소에서 낼 실수는
아니라서요.

데스크톱·모바일(390px), 라이트·다크 양쪽에서 확인했습니다 — 4컬럼이 900px에서
2컬럼, 560px에서 1컬럼으로 접히고 **가로 스크롤 없음**, 푸터 링크 18개 전부 실재
경로(커밋 전 파일 존재 확인), 콘솔 에러 없음.
