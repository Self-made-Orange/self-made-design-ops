# 이벤트 택소노미 규약

제품 분석 이벤트를 정의할 때 쓰는 **공용 작성 규약**입니다.
특정 제품의 이벤트 정의는 여기 두지 않습니다 — 그건 해당 제품 저장소에 속합니다.

이 규약은 실제 제품의 MVP 이벤트 시트 작업에서 쓰인 형식을 일반화한 것입니다.
제품 고유 데이터는 제외했습니다. **제품명은 여기 적지 않습니다** — 적는 순간, 이 절이
저장소에 두지 않는다고 말한 바로 그것이 새어 나갑니다.

## 시트 컬럼

| 컬럼 | 내용 | 필수 |
|------|------|:----:|
| 카테고리 | 기능 영역. 이벤트 접두사와 일치시킵니다 | O |
| 이벤트명 | `{도메인}_{동작}` | O |
| 화면 위치 | 사용자 경로 표기. `홈 > 수동 입력` 형식 | O |
| 트리거 | 이벤트가 발생하는 조건을 한 문장으로 | O |
| 프로퍼티 키 | 함께 전송할 속성명 | |
| 프로퍼티 값 / 타입 | enum이면 값 나열, 아니면 타입명 | |
| 조건 / 비고 | 필수 여부, 조건부 전송 규칙 | |

`template.csv`에 헤더만 있는 빈 시트가, `example.csv`에 작성 예시가 있습니다.

## 명명 규칙

### 이벤트명은 `{도메인}_{동작}`

```
sdk_view      sdk_click
chart_view    chart_click
```

동작은 `view`(화면 진입)와 `click`(요소 탭)을 기본으로 씁니다.
이 둘로 안 되는 경우에만 새 동작을 추가하고, 추가하면 규약에 반영합니다.

도메인은 카테고리 컬럼과 일치시킵니다. 시트를 카테고리로 정렬하면 이벤트도 같이 묶입니다.

### 화면마다 이벤트를 만들지 않습니다

13개 화면이 있어도 이벤트는 `sdk_view` 하나로 두고, 화면은 `screen_name` 프로퍼티로 구분합니다.

```
이벤트명   프로퍼티 키    값
sdk_view   screen_name   scan_qr | device_found | analyzing | ...
```

이유:
- 이벤트 개수가 화면 수만큼 늘어나면 대시보드에서 다루기 어려워집니다
- 화면이 추가돼도 이벤트 스펙 변경 없이 enum 값만 늘리면 됩니다
- 퍼널 분석 시 같은 이벤트 안에서 단계를 비교할 수 있습니다

역으로, **도메인이 다르면 이벤트를 분리합니다.** 홈과 차트를 `app_view` 하나로 합치지 않습니다.

### enum은 파이프로 나열

```
menstrual | pre_fertile | fertile | ovulation | post_fertile | luteal
```

값이 확정되지 않았으면 `ovulation | …` 처럼 말줄임을 붙여 미확정임을 드러냅니다.
빈칸으로 두면 누락인지 미정인지 구분되지 않습니다.

## 조건부 프로퍼티

모든 프로퍼티가 항상 붙지는 않습니다. 이런 경우 **이벤트명 행 아래에 프로퍼티만 이어서 적고**,
카테고리·이벤트명·화면 위치·트리거는 비웁니다.

```csv
SDK,sdk_view,기기 연결 > [screen_name],화면 진입,screen_name,"scan_qr | device_found | ...",필수
SDK,sdk_view,,,is_new_device,boolean,device_found 화면에서만
SDK,sdk_view,,,device_id,string,device_found 이후 화면에서만
```

- 항상 붙는 프로퍼티는 조건 컬럼에 `필수`
- 조건부는 **언제 붙는지를 조건 컬럼에 명시**합니다. "가끔"이나 공란은 구현자가 판단할 수 없습니다
- 이벤트명은 매 행 반복해서 적습니다. 정렬·필터가 깨지지 않게 하기 위해서입니다

## 화면 위치에 변수 쓰기

`기기 연결 > [screen_name]` 처럼 대괄호로 프로퍼티를 참조할 수 있습니다.
같은 이벤트가 여러 화면에서 발생할 때, 화면마다 행을 늘리지 않고 한 줄로 표현합니다.

## 작성 순서

1. **카테고리를 먼저 나눕니다.** 기능 영역 단위이며, 보통 3~6개입니다
2. 각 카테고리에서 `_view` / `_click` 두 이벤트로 시작합니다
3. 화면·버튼은 이벤트를 늘리지 말고 `screen_name` / `button_name` enum으로 넣습니다
4. 프로퍼티를 붙이고, 조건부인 것은 조건을 반드시 적습니다
5. enum 값이 미정이면 `…`로 표시하고 남겨둡니다

## 검토 항목

시트를 넘기기 전에 확인합니다.

- [ ] 모든 이벤트가 `{도메인}_{동작}` 형식인가
- [ ] 카테고리와 이벤트 접두사가 일치하는가
- [ ] 화면 단위로 이벤트를 쪼개지 않았는가
- [ ] 조건부 프로퍼티에 **언제 붙는지**가 적혀 있는가
- [ ] 필수 프로퍼티에 `필수` 표기가 있는가
- [ ] enum 값이 미정인 곳에 `…` 표시가 있는가
- [ ] 제품 고유 데이터가 이 저장소에 섞여 들어오지 않았는가

## 변환 스크립트

`convert.mjs` — 시트를 팀이 쓰는 포맷으로 변환합니다. 의존성 없음, Node 18+ / Bun.

```bash
node convert.mjs sheet.csv --to html -o taxonomy.html
node convert.mjs sheet.csv --lint-only
```

| 타깃 | 결과물 | 용도 |
|------|--------|------|
| `json` | 구조화 JSON | 앱에서 읽기, 다른 도구로 넘기기 |
| `md` | 마크다운 | 저장소 문서, PR 리뷰 |
| `html` | 단독 HTML (검색·다크모드) | 공유, 인쇄 |
| `tsv` | 탭 구분 | Google Sheets · Excel 붙여넣기 |
| `notion` | CSV | Notion DB 임포트 |

### 그룹핑이 핵심입니다

단순 포맷 변환이 아닙니다. 규약상 조건부 프로퍼티는 이벤트명 아래 **빈 칸으로 이어지는 행**에
적는데, 그대로 옮기면 어느 포맷에서도 빈 칸투성이가 됩니다.
스크립트는 먼저 이벤트 단위로 묶은 뒤 렌더링합니다.

```
CSV (사람이 편집하기 좋은 형태)      →  이벤트 객체  →  각 포맷
카테고리 이벤트명 화면 트리거 키 값 조건
SDK     sdk_view  …    …    screen_name  …  필수
        (빈칸)   (빈칸)(빈칸) is_new_device …  device_found에서만
```

### Notion·스프레드시트는 평면화합니다

두 도구 모두 계층을 모릅니다. 빈 칸이 있으면 필터·정렬·그룹핑이 깨지므로,
이 두 타깃만 **빈 칸을 앞 값으로 채운 완전 평면 표**를 냅니다.
`필수` 컬럼도 `TRUE`/`FALSE`로 분리해서 체크박스 속성으로 잡히게 합니다.

### 린터

`--lint-only`로 규약 위반만 검사합니다. 아래 체크리스트를 코드로 옮긴 것입니다.

- 이벤트명이 `{도메인}_{동작}` 형식인가
- 카테고리와 이벤트 접두사가 일치하는가
- 트리거·프로퍼티가 비어 있지 않은가
- 조건부 프로퍼티에 **언제 붙는지**가 적혀 있는가
- enum에 미확정(`…`) 표시가 남아 있는가

`--strict`를 붙이면 위반 시 변환하지 않고 종료하므로 CI에 걸 수 있습니다.

## 범위 밖

**특정 제품의 이벤트 정의는 이 저장소에 두지 않습니다.** 해당 제품 저장소로 보냅니다.
여기 남는 것은 규약과 빈 템플릿뿐입니다.

그 제품의 MVP 이벤트 시트가 이 저장소에 있었으나 제품 고유 데이터라 제거했습니다.

> **파일을 지운다고 지워지지 않습니다.** 이 시트는 삭제되기 전에 `main`에 머지됐고,
> 그래서 히스토리를 재작성하기 전까지 블롭이 계속 접근 가능한 상태로 남아 있었습니다.
> 파일을 지우고 "제품 데이터를 제거했다"고 적는 건 삭제가 아니라 **데이터 옆에 붙인
> 메모**입니다. 정말 민감한 건 첫 커밋에 안 들어가게 하거나, 사후에 히스토리에서
> 파내야 합니다.
