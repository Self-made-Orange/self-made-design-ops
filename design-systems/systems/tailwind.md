## In one line

A utility-class CSS framework. From v4 on, **the entire theme is one file of CSS variables**
(`theme.css`), and it ships no components — **only the token layer**.

> **A note on classification.** Every other entry in this corpus is a design system a
> company built for its own product. Tailwind has no product; it is a **framework**, so it
> is marked `domain: framework` (see `SCHEMA.md`). The same applies to shadcn/ui, Mantine
> and Radix Themes below.

## Tokens

### Spacing — the only system in the sample that does not enumerate a scale

```css
--spacing: 0.25rem;   /* 4px. That is all of it */
```

**There are no steps.** `p-3` is `calc(var(--spacing) * 3)` = 12px, **generated by
multiplication**. Not only integers work: `p-1.5` (6px) and `p-2.5` (10px) are valid too.

| approach | systems |
|------|--------|
| enumerate the steps | everything else in the sample |
| **one base plus multiplication** | **Tailwind v4** |

This differs from Ant Design **deriving** its scale from `sizeUnit` and `sizeStep` — Ant
emits the derived results as a finite list of tokens, whereas Tailwind **never produces the
list at all.**

**Practical consequence:** there is no scale to carry into a design tool. To export to
Figma Variables you must pick and enumerate the steps you intend to use.

### Typography

Size and line height are **bound together in pairs** (`--text-*` +
`--text-*--line-height`).

| token | size | line-height definition | computed |
|------|:---:|-----------|:---:|
| `xs` | 0.75rem (12) | `calc(1 / 0.75)` | 1.333 (16px) |
| `sm` | 0.875rem (14) | `calc(1.25 / 0.875)` | 1.429 (20px) |
| `base` | 1rem (16) | `calc(1.5 / 1)` | 1.5 (24px) |
| `lg` | 1.125rem (18) | `calc(1.75 / 1.125)` | 1.556 (28px) |
| `xl` | 1.25rem (20) | `calc(1.75 / 1.25)` | 1.4 (28px) |
| `2xl` | 1.5rem (24) | `calc(2 / 1.5)` | 1.333 (32px) |
| `3xl` | 1.875rem (30) | `calc(2.25 / 1.875)` | 1.2 (36px) |
| `4xl` | 2.25rem (36) | `calc(2.5 / 2.25)` | 1.111 (40px) |
| `5xl` | 3rem (48) | `1` | 1 |
| `6xl` | 3.75rem (60) | `1` | 1 |
| `7xl` | 4.5rem (72) | `1` | 1 |
| `8xl` | 6rem (96) | `1` | 1 |
| `9xl` | 8rem (128) | `1` | 1 |

**Line height is written as a ratio, but the original intent is a px value.** The numerator
of `calc(1.25 / 0.875)`, 1.25rem, is 20px — **a px line height converted into a ratio**.
From `5xl` up they are all `1`.

Separate tokens exist for specifying line height on its own.

| token | value |
|------|:---:|
| `--leading-tight` | 1.25 |
| `--leading-snug` | 1.375 |
| `--leading-normal` | 1.5 |
| `--leading-relaxed` | 1.625 |
| `--leading-loose` | 2 |

Tracking — in `em`, three steps on each side of 0:

| token | value |
|------|:---:|
| `tighter` | -0.05em |
| `tight` | -0.025em |
| `normal` | 0em |
| `wide` | 0.025em |
| `wider` | 0.05em |
| `widest` | 0.1em |

**Three symmetric steps on both sides of 0**, unlike Backpack and Seed Design, which offer
only negatives (`patterns/typography.md`).

Nine weights: 100 · 200 · 300 · 400 · 500 · 600 · 700 · 800 · 900 —
`--font-weight-thin` through `--font-weight-black`, every hundred.

### Colour — 286 of them, 26 hues × 11 steps

| family | |
|------|--|
| achromatic | `gray` · `slate` · `zinc` · `neutral` · `stone` · **`mauve`** · **`mist`** · **`olive`** · **`taupe`** |
| chromatic | `red` · `orange` · `amber` · `yellow` · `lime` · `green` · `emerald` · `teal` · `cyan` · `sky` · `blue` · `indigo` · `violet` · `purple` · `fuchsia` · `pink` · `rose` |

The steps are `50 · 100 · 200 … 900 · 950` — **11 of them**, identical across all 26 hues.
Adding `--color-black` and `--color-white` brings the total to 288.

**`mauve` · `mist` · `olive` · `taupe` sit in the achromatic family.** Other systems in the
sample keep one or two grey families. Tailwind has nine.

**There is no semantic layer.** There are no role tokens like `text-primary` or `surface`,
only raw colours. The role layer is the user's to build — which is exactly what shadcn/ui
does.

### Breakpoints and containers

Five breakpoints, **in `rem`**.

| token | value | px (at 16px) |
|------|:---:|:---:|
| `sm` | 40rem | 640 |
| `md` | 48rem | 768 |
| `lg` | 64rem | 1024 |
| `xl` | 80rem | 1280 |
| `2xl` | 96rem | 1536 |

Thirteen container max-widths — from `3xs` 16rem to `7xl` 80rem:
`3xs · 2xs · xs · sm · md · lg · xl · 2xl · 3xl · 4xl · 5xl · 6xl · 7xl`.

**Breakpoints and containers are separate families.** The `xl` breakpoint (80rem) and the
`7xl` container (80rem) hold the same value under different names.

### Other token families

| family | steps | values |
|------|:---:|------|
| `--blur-*` | 7 | 4 · 8 · 12 · 16 · 24 · 40 · 64px |
| `--shadow-*` | 9 | not recorded (composite values) |
| `--ease-*` | 3 | `in` · `out` · `in-out` (cubic-bezier) |
| `--animate-*` | 4 | `spin` · `ping` · `pulse` · `bounce` |
| **`--perspective-*`** | **5** | `dramatic` 100 · `near` 300 · `normal` 500 · `midrange` 800 · `distant` 1200px |
| `--text-shadow-*` | 5 | `2xs` – `lg` |
| `--default-transition-duration` | 1 | 150ms |

**`--perspective-*` is a token.** Tailwind is the only system in the sample that puts 3D
perspective distance into named steps.

The global transition default is a token too — `150ms` / `cubic-bezier(0.4, 0, 0.2, 1)`.

## Components

**None.** Only utility classes and tokens.

## Characteristic decisions

- **It does not enumerate spacing.** Everything is generated by multiplying the single
  `--spacing: 0.25rem`. Unique among the 34 samples.
- **There is no semantic colour layer.** Only 286 raw colours. Where other systems keep a
  two-tier `scale/` + `semantic/` structure, Tailwind keeps one tier.
- **There are nine achromatic families**, including `mauve` · `mist` · `olive` · `taupe`.
- **Line height is attached to the size token** — `--text-sm--line-height`, using a double
  hyphen to express a token's sub-property. Tailwind is the only place in the sample using
  this notation.
- **`rem` breakpoints.** Most systems use px. Here the breakpoints respond to the user's
  font-size setting.
- **Families like `--perspective-*` and `--text-shadow-*` are tokens.** The tokenised
  surface is wider than in other systems.
- **There is no runtime multiplier variable.** It does not use the
  `calc(var(--scale) * N)` approach of Mantine, Radix Themes and Vapor UI. Changing
  `--spacing` itself moves all spacing with it, so the same adjustment is possible in
  effect.

## Accessibility

The files state no accessibility target at the token or CSS level. With no components,
ARIA and focus management are out of scope.
