## In one line

IBM's design system for enterprise products, designed on the premise of data-dense working
screens.

### Typography

The typeface is **IBM Plex** (Sans / Mono / Serif). The size scale is defined not as a list
of values but as **a recursive function**.

```scss
@function get-type-size($step) {
  @if $step == 1 { @return 12px; }
  @return get-type-size($step - 1) + (math.floor(($step - 2) * 0.25) + 1) * 2;
}
```

The increment grows every four steps (+2 → +4 → +6 → +8 …), and 23 steps are generated.

```
12, 14, 16, 18, 20, 24, 28, 32, 36, 42, 48, 54, 60, 68, 76, 84, 92, 102, 112, 122, 132, 144, 156
```

Note: a comment in the source states the officially supported range as **12–92px**
(17 steps). The values past the 18th step are generated by the function but lie outside that
range. The list above was recovered by running the function.

Source: `@carbon/type@11.65.0` → `scss/_scale.scss`, `scss/_font-family.scss`

#### Three weights · eleven families (added 2026-08-18)

`$font-weights`: `light` **300** · `regular` **400** · `semibold` **600**.
**There is no 700 (bold).**

Eleven `$font-families` — `sans` · `sans-condensed` · `serif` · `mono` plus
**seven per-language faces** (`sans-arabic` · `sans-devanagari` · `sans-hebrew` ·
`sans-jp` · `sans-kr` · `sans-thai` · `sans-thai-looped`). All are IBM Plex, and the
fallback is the shared `system-ui, -apple-system, BlinkMacSystemFont, '.SFNSText-Regular'`.
**Only Thai gets two sets, looped and non-looped.**

`font-size`, `font-weight`, `line-height` and `letter-spacing`**.

| `label-02` · `legal-02` · `helper-text-02` | 14px | 400 | 1.28572 | 0.16px |
| `body-short-01` | 14px | 400 | 1.28572 | 0.16px |
| `body-long-01` | 14px | 400 | **1.42857** | 0.16px |
| `body-short-02` | 16px | 400 | 1.375 | 0 |
| `body-long-02` | 16px | 400 | **1.5** | 0 |
| `code-01` | 12px (mono) | 400 | 1.33333 | 0.32px |
| `code-02` | 14px (mono) | 400 | 1.42857 | 0.32px |
| `heading-01` | 14px | **600** | 1.42857 | 0.16px |
| `productive-heading-01` | 14px | 600 | 1.28572 | 0.16px |
| `heading-02` | 16px | 600 | 1.5 | 0 |
| `productive-heading-02` | 16px | 600 | 1.375 | 0 |
| `productive-heading-03` | 20px | 400 | 1.4 | 0 |
| `productive-heading-04` | 28px | 400 | 1.28572 | 0 |
| `productive-heading-05` | 32px | 400 | 1.25 | 0 |
| `productive-heading-06` | 42px | **300** | 1.199 | 0 |
| `productive-heading-07` | 54px | 300 | 1.19 | 0 |

- **The `short`/`long` pairs share a size and differ only in line height** (14px: 1.28572 vs
  1.42857 / 16px: 1.375 vs 1.5). A single line and a paragraph are separated by leading
  rather than by size.
- There are **two families, `productive` and `expressive`.** The ten
  `expressive-heading-03`–`06` · `quotation-01/02` · `display-01`–`04` styles
  **embed per-breakpoint values in the token**
  (`breakpoints: (md: (…), lg: (…), xlg: (…), max: (…))`).
  For instance `display-04` runs 42 → md 68 → lg 92 → xlg 122 → max 156px.
- Tracking is 0.32px at 12px, 0.16px at 14px and 0 from 16px up —
  **the smaller the size, the looser the tracking** (the opposite direction from Cloudscape
  and Polaris).
- `caption-01/02` carry an `@deprecated` marker.
- In the ten breakpoint styles **the weight changes along with the size**
  (`expressive-heading-05`: 32px/400 → md 36px/**300**).

Source: `@carbon/type@11.65.0` → `scss/_styles.scss`, `scss/_font-family.scss`

#### The raw palette — 13 families × 10 steps + **hover twins**

`blue` · `cyan` · `gray` · `cool-gray` · `warm-gray` · `green` · `magenta` ·
`orange` · `purple` · `red` · `teal` · `yellow` (12), each in **10 steps (10–100, by 10)**.
**There are three greys** — neutral (`gray`), cool (`cool-gray`) and warm (`warm-gray`).
`black` (`black-100`) and `white` (`white-0`) are separate.

**Every swatch has a `-hover` twin.**

```scss
$blue-60:       #0f62fe;
$blue-60-hover: #0050e6;
$white:         #ffffff;
$white-hover:   #e8e8e8;
```

124 non-hover variables (120 plus `black-100` · `white-0` · `black` · `white`) +
122 hover + the `$colors` map = 247 variables.
**Carbon is the only system in the corpus to put interaction state in the raw palette
rather than the semantic layer.**
There are stretches where `-70-hover` is lighter than `-60` (`blue-70-hover: #0053ff`), so
it is not a simple shift in lightness.

**There is no alpha family** — every value is an opaque six-digit hex.

### Contextual layout tokens — size is inherited from the context

```scss
$layout-tokens: (
  size:    ( height: ( xs 24 · sm 32 · md 40 · lg 48 · xl 64 · 2xl 80 ) ),
  density: ( padding-inline: ( condensed $spacing-03 · normal $spacing-05 ) ),
);
@include layout.use('size', $default: 'md', $min: 'sm', $max: 'lg');
```

A component **declares the size range it supports (min/max)** and receives the actual size
from the surrounding layout context — a text input's height is a single
`layout.size('height')` reference. The same "context decides the value" family as
Cloudscape's density modes, but **Carbon alone puts all six size steps on the context
axis.**

### Button measurements

| item | value |
|------|-----|
| default height | **48px** (3rem) — at the top of the corpus distribution |
| **min-width** | **176px** (`$button-min-inline-size`) — a button min-width token is unique in the sample |
| radius / border | **0** / 2px |
| padding | `calc(0.875rem − 3px)` — the border and outline back-computed out (the Radix-family formula) |
| type | 14px / 400 |

### Elsewhere

- **Modal widths are viewport percentages, not px** — 48% / 60% / 84% by size and
  breakpoint (in contrast to the fixed-px camp of shadcn's 512px and Mantine's 440px;
  cross-referenced in `patterns/modal.md`)
- Checkbox **16px** (the convergent value), a 9×5px check mark, no notion of a touch target
  — the opposite pole from GOV.UK's 40px (a desktop-enterprise premise)
- High-contrast support sits directly in the component source:
  `border: 1px solid ButtonBorder` (a forced-colors system colour keyword)

## Components in depth — tables, navigation, feedback (2026-08-18)

Measured from the `scss/components/` SCSS of `@carbon/styles@1.113.0`
(against `$spacing-01`–`13` = 2/4/8/12/16/24/32/40/48/64/80/96/160px).

### Tables (`data-table`) — five density steps, straight off the layout-token ladder

| size | row height | cell block padding |
|:---:|:--:|:--:|
| xs | **24px** | 2 / 2px |
| sm | 32px | 7 / 6px |
| md | 40px | 7 / 6px |
| **lg (default)** | **48px** (`$spacing-09`) | `$spacing-05` = 16 / 16px |
| xl | **64px** | 16 / 16px |

- **Five density steps, the most in the sample collected** (Vuetify, Chakra, PrimeVue, Semi
  and Naive have three; Cloudscape two). The values match the `size.height` ladder in
  `utilities/_layout.scss` **exactly** (xs 24 / sm 32 / md 40 / lg 48 / xl 64 / 2xl 80) —
  the table has no dimensional system of its own and uses the shared contextual layout
  tokens.
- **The cell block padding is asymmetric at 7 / 6px** (sm and md). The 13px total plus the
  line height produces 32 and 40px, and the values fall off any multiple of 4.
- The cell inline padding is **fixed at `$spacing-05` (16px) across every step** — the
  Cloudscape and Semi camp, where density reduces only the vertical.
- **There is a 1px border both above and below,** but the top one is `$layer` (the
  background colour) — on hover and selection only the top border takes a colour, so
  **the layout does not shift.**
- The sticky header switches to `display: flex` plus `position: sticky` plus
  **`z-index: 1`** plus `will-change: transform`.
- **The sort icon is 20px and sits at `opacity: 0` while unsorted**, going to 1 when sorting
  is active. Descending is a `transform: rotate(180deg)` with a transition — the code-layer
  implementation of the three-state rule (unsorted → up → down) stated in the documentation
  layer.
  The sorted column's header background changes to `$data-table-column-hover`.
- Zebra striping (`--zebra`) is `nth-child(odd)`, and its combinations with selection and
  hover are enumerated across eight separate selectors.

### Navigation (`ui-shell/side-nav` · `tabs` · `breadcrumb`)

The UI Shell uses the formula `mini-units(n) = 0.5rem × n`.

| item | value |
|---|---|
| side navigation width | `mini-units(32)` = **256px** |
| rail (icon) width | `mini-units(6)` = **48px** |
| item min-height | `mini-units(4)` = **32px** · large `mini-units(6)` = 48px |
| item inline padding | `mini-units(2)` = 16px |
| item type | 14px / 20px line height / 0.1px tracking · active weight **600** |
| level indent | `mini-units(4)` = **32px** · second level with an icon `mini-units(9)` = 72px |
| **active marker** | a **3px** bar on the left (`::before`, `$border-interactive`) |
| header height | **48px** (back-computed from `calc(100% - 48px)`) |
| tab height | `layout.size('height')` — the xs 24 to 2xl 80 ladder |
| active tab underline | **2px** (`$border-interactive`) · inactive `$tab-underline-color` 2px `$border-subtle` |
| tab inline padding | `layout.density('padding-inline')` — condensed 8 / normal 16px |
| breadcrumb separator margin | `$spacing-03` = **8px** · item margin 8px |

- **Expanded 256 / collapsed 48** is exactly the same as shadcn/ui. Two unrelated systems
  arrived at the same pair of values.
- **The active marker is a 3px vertical bar on the left** — a fourth approach alongside the
  underline, pill and background, and the case in the sample of a vertical indicator in a
  side navigation.
- **Inactive tabs carry a 2px underline too** (only the colour differs,
  `$border-subtle`) — the thickness does not change on becoming active. The same idea as
  Semi keeping its hover underline at the same weight.
- Tabs and tags **inherit their size from the context via `layout.use('size', …)`**
  (see "contextual layout tokens" above) — the same mechanism as the table.

### Feedback (`notification` · `tag`)

| item | value |
|---|---|
| **toast width** | **288px** → **352px** at the `max` breakpoint |
| toast left padding | **13px** (19px together with the 6px accent border) |
| **left accent border** | **6px** (toast and inline) · the low-contrast variant **3px** |
| inline notification min-height | **48px** · min-width 288px |
| inline notification max-width | **288 → 608 → 736 → 832px** (four breakpoints) |
| close button | **48×48px** (min-block/inline-size) |
| **tag height** | xs and sm **18px** / **md 24px (default)** / lg 32px |
| tag radius and padding | **16px (a pill)** · inline `$spacing-03` (8px) |
| tag width limits | max **208px** · min 32px |

- **The toast width is responsive** (288 → 352px). The only case in the sample collected of
  changing a toast's width by breakpoint — the rest are fixed
  (Sonner 356 · PrimeVue 352 · Ant and Grommet 384 · Naive 365) or have no width (Semi).
- **The 6px left accent border** is the second thickest in the sample after Vuetify's 8px
  (EUI 3 · Cloudscape 2). **It halves to 3px in the low-contrast variant alone** — as the
  background lightens, the accent line is taken thinner too.
- **The close button is 48×48px** — a case of applying a touch-target spec to dismissing a
  notification, taking up a sixth of the toast's 288px width.
- The tag **overrides the shared height ladder to 18/18/24/32 with
  `layout.redefine-tokens`** — a structure in which the same step names hold different
  values per component.

## Characteristic decisions

- **There are fine 2 and 4px units at the bottom of the spacing scale.** A base-8 system
  that nonetheless provides 2px and 4px as `$spacing-01/02`.
- **The type scale is a function.** The values are generated by an increment rule rather
  than picked by hand — the advantage being that no arbitrary judgement enters when the
  scale is extended.
- **The top of the spacing scale jumps to 160px.** 96 → 160 is a larger leap than the other
  steps (1.3–1.5×).

- **Hover colours ship as pairs in the raw palette** (2026-08-18). Each of the 122 swatches
  has a `-hover` twin (`$blue-60` / `$blue-60-hover`).
  The corpus majority builds interaction state at the semantic layer; Carbon
  **starts out with state already present at the raw layer.**

- **There are three grey ramps** — neutral `gray`, cool `cool-gray` and warm `warm-gray`.
  Ten steps each, so the greys alone number 30.

- **Colour has a layer axis too.** The 29 `layer*` tokens including `layer01/02/03` build
  the same "context decides the surface colour" structure as the contextual layout tokens
  in spacing.

- **There is a colour family dedicated to generative AI** — 21 `ai*` tokens (aura, border,
  popover shadow) and 21 `chat*`. Carbon is the system in the sample that raised AI UI
  colours into a token family.

- **The weight ceiling is 600** (`light` 300 · `regular` 400 · `semibold` 600).
  There is no 700 — the same as Primer.

- **Tracking is loosened on small text** (0.32px at 12px → 0 from 16px up).
  The opposite direction from Cloudscape and Polaris, which tighten into the negative as
  the size grows.
