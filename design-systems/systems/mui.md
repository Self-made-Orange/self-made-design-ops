## In one line

The most widely used React component framework — its body default is **14px**, and the rem
conversion multiplies by a **`fontSize/14` correction coefficient**, so changing the base
size **recalculates the entire scale proportionally**. Material lineage, but it does not
use M3's token structure.

## Tokens — a theme generated by functions

```js
htmlFontSize = 16      // the root (browser default)
fontSize     = 14      // MUI's body default
coef = fontSize / 14   // change the base and this coefficient multiplies every size
pxToRem = size => `${size / htmlFontSize * coef}rem`
fontWeightLight 300 · Medium 500
```

- **`coef` is a form of correction unique in the sample** — set `fontSize: 16` and
  `coef = 16/14 ≈ 1.143`, making **all typography 14% larger**. The same purpose as runtime
  scaling (Mantine's `--mantine-scale`), through a structure where **changing the base size
  *is* the scaling**
- **A 14px body** — the dense enterprise camp (Ring UI, Siemens iX, Naive UI, PrimeVue…).
  It took Material 3's Body Medium (14) rather than Body Large (16) as its default
- **It exposes the `rem` conversion function (`pxToRem`) on the theme** — distributing
  **a converter** rather than token values, the same "ship a function" camp as SmartHR
  (state colour functions) and Naive UI (colour composition)
- `spacing` is a function taking an input (`spacingInput`) — 8px multiples by default, used
  as `theme.spacing(2)` = 16px. The same **base × multiplier generation** as Tailwind, but
  as a runtime function call
- The weights include `300` (Light) — the minority camp, with Yoga

### Buttons — the height is not fixed

No height is declared; it is **derived from type × a 1.75 line height + vertical padding**.

| | small | medium | large |
|---|:--:|:--:|:--:|
| Type | 13px | 14px | 15px |
| Vertical padding (contained) | 4px | 6px | 8px |
| Horizontal padding (contained) | 10px | 16px | 22px |
| Horizontal padding (outlined) | 9px | 15px | 21px |
| Horizontal padding (text) | 5px | 8px | 11px |
| **Derived height** | **30.75px** | **36.5px** | **42.25px** |

- **The button heights are fractional** — with a unitless 1.75 line height, 13 × 1.75 =
  22.75px and integers do not come out. A fundamentally different layer from the 36 and
  40px integer-height camp.
- **The outlined padding is 1px smaller than contained in each direction** — subtracting
  the 1px border from the padding so all three variants come to the same total dimensions
  (the same intent as Garden's `height − 2px` line-height back-computation).
- Minimum width **64px**, radius `shape.borderRadius` = **4px**.
- The type is **forced uppercase** plus weight 500 plus 0.02857em tracking
  (back-computed as 0.4px/14px).
- Transition: background, shadow, border and colour over **250ms `(0.4,0,0.2,1)`**.

### Inputs (TextField/OutlinedInput) — half-pixel padding

| | small | medium |
|---|:--:|:--:|
| Content line height | 1.4375em (**23px**) | 23px |
| Vertical padding | **8.5px** | **16.5px** |
| Horizontal padding | 14px | 14px |
| **Derived height** | **40px** | **56px** |

- **The vertical padding is a half pixel, 8.5/16.5px** — with an odd 23px content line, this
  compensates to bring the total to an integer 40 or 56px. Buttons (36.5px) are not
  compensated; only inputs are.
- **The label floats inside the input and then shrinks and moves** (outlined):
  `translate(14px, 16px) scale(1)` → `translate(14px, -9px) scale(0.75)` — a 16px label
  shrinking to 75%, becoming 12px, and sitting in the notch in the border. A Material-lineage
  floating label, diverging from most of the sample (a fixed block label above).
- Three variants: outlined · filled (`25px 12px 8px` — the label's share folded into the top
  padding) · standard (`4px 0 5px`, an underlined form with no border).

### Dialogs — the width steps *are* the breakpoints

| maxWidth prop | Real width |
|------|-----|
| `xs` | **max(breakpoint xs, 444px) = 444px** |
| `sm` | 600px |
| `md` | 900px |
| `lg` | 1200px |
| `xl` | 1536px |

- **There is no dedicated width scale** — it uses the breakpoint values directly (the
  opposite pole from Cloudscape's dedicated five steps, 320–1280). The only exception is
  the **444px** floor on xs, pinned in the code as
  `Math.max(theme.breakpoints.values.xs, 444)`.
- Margins: **32px** on all sides, with a `maxWidth: calc(100% − 64px)` ceiling.
- Radius 4px (inherited from Paper), shadow **elevation 24** — the top of a 25-step shadow
  scale assigned to dialogs.
- Animation: Fade (opacity only), **225ms entering / 195ms leaving**, `(0.4,0,0.2,1)` —
  **asymmetric entry and exit durations as `enteringScreen` / `leavingScreen` tokens** on
  the theme.
- Inner padding: title `16px 24px` · body `20px 24px` · actions `8px`.

### Notable decisions (deep-dive)

- **Fractional button heights (36.5px) left alone versus half-pixel input padding (16.5px)
  compensated** — an asymmetry where only one of the two derived heights is corrected to an
  integer within the same system
- **Dialog widths = the breakpoints reused**, with a single 444px exception
- **Asymmetric entry/exit durations (225/195ms) tokenised** — rare in the sample
- **Outlined padding subtracting 1px** — offsetting the border's share from the padding
- v9 is still an emotion runtime, but variant colours are assembled through **a CSS-variable
  indirection layer** like `--variant-containedBg` — a CSS-variable architecture arriving
  inside CSS-in-JS

## Notable decisions

- **The `coef = fontSize/14` correction coefficient** — a structure unique in the sample,
  where changing the base becomes a global scaling
- A 14px body (the M3 Body Medium family)
- It distributes **a conversion function (`pxToRem`) and a generator (`createTheme`)**
  rather than tokens
- Spacing as a function call (`theme.spacing(n)`) — no list. The third member of the
  "don't enumerate" camp in `tokens/scales.md` (after Tailwind and Ring UI)
