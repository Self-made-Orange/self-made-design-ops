# 로컬라이제이션 규약

다국어 문자열을 정의·관리할 때 쓰는 **공용 규약**입니다.
특정 제품의 실제 번역 문자열은 여기 두지 않습니다 — 해당 제품 저장소에 속합니다.

`event-taxonomy/`와 같은 구조입니다 — **규약 + 템플릿 + 검사 스크립트.**

## 왜 규약이 필요한가

번역은 문자열을 바꾸는 일이 아니라 **레이아웃과 문법을 바꾸는 일**입니다.
아래 셋이 실제로 깨지는 지점입니다.

1. **길이가 변합니다.** 독일어는 영어보다 길고, 한국어·중국어는 짧습니다
2. **복수형 규칙이 언어마다 다릅니다.** 한국어는 1개, 영어는 2개, 아랍어는 6개입니다
3. **본문 글자 크기 관행이 다릅니다.** 이건 이 저장소의 코퍼스에서 확인된 사실입니다

## 로케일 식별자 — BCP 47

```
ko-KR          언어-지역
zh-Hans-CN     언어-문자-지역  (간체)
zh-Hant-TW     언어-문자-지역  (번체)
en             지역 구분이 불필요하면 언어만
```

**중국어는 반드시 문자(script) 서브태그를 씁니다.** `zh-CN`·`zh-TW`는
지역으로 문자를 추정하게 만들어 홍콩 번체(`zh-Hant-HK`) 같은 경우를 처리할 수 없습니다.

**임의 코드를 만들지 마세요.** `kr`(존재하지 않음, 한국어는 `ko`) ·
`cn`(존재하지 않음, 중국어는 `zh`) · `en_US`(BCP 47은 하이픈) 이 흔한 실수입니다.

## 키 명명

```
<화면>.<요소>.<용도>

home.cta.primary
settings.notification.toggle_label
checkout.error.card_declined
```

- **소문자 스네이크케이스 + 점 구분**
- **화면 → 요소 → 용도** 순서로 좁혀갑니다
- **번역문을 키로 쓰지 않습니다.** `"결제하기": "Pay"` 같은 방식은
  원문이 바뀔 때마다 키가 깨지고, 같은 단어의 다른 맥락을 구분할 수 없습니다

`event-taxonomy/`의 `{도메인}_{동작}`과 같은 원칙입니다 — **구조를 이름에 담습니다.**

### 같은 단어라도 맥락이 다르면 키를 나눕니다

```
common.action.close        닫기 (동작)
common.state.closed        마감됨 (상태)
```

영어로는 둘 다 "Close"에 가깝지만, 한국어·독일어에서 다른 단어가 됩니다.
**한 키를 여러 자리에서 재사용하면 번역자가 맥락을 알 수 없습니다.**

## 복수형 — ICU MessageFormat

문자열을 이어 붙이지 말고 **ICU MessageFormat**을 씁니다.

```
{count, plural,
  one {# item}
  other {# items}}
```

### 언어별 복수형 카테고리 (CLDR)

| 언어 | 카테고리 | 개수 |
|------|----------|:---:|
| 한국어 · 일본어 · 중국어 · 베트남어 · 태국어 | `other` | **1** |
| 영어 · 독일어 · 네덜란드어 · 스페인어 · 이탈리아어 | `one` · `other` | 2 |
| 프랑스어 · 포르투갈어(BR) | `one` · `many` · `other` | 3 |
| 러시아어 · 우크라이나어 · 폴란드어 | `one` · `few` · `many` · `other` | 4 |
| 아랍어 · 웨일스어 | `zero` · `one` · `two` · `few` · `many` · `other` | **6** |

**한국어는 복수형이 없습니다.** `other` 하나만 있으면 됩니다.
반대로 **아랍어는 6개를 다 채워야** 하며, 하나라도 빠지면 그 수량에서 문장이 깨집니다.

**절대 하지 말아야 할 것:**

```
❌ count === 1 ? '1개 항목' : `${count}개 항목`      // 영어 규칙을 하드코딩
❌ `${count}` + t('items')                          // 문자열 이어 붙이기
✅ {count, plural, other {#개 항목}}                 // ICU
```

이어 붙이기는 어순이 다른 언어에서 반드시 깨집니다.

### 성별·선택

```
{gender, select,
  male {그가}
  female {그녀가}
  other {그 사람이}}
```

`other`를 **항상** 포함합니다. 값이 예상 밖일 때의 폴백입니다.

### 숫자·날짜·통화

포맷을 문자열에 박지 말고 ICU 인자를 씁니다.

```
{value, number}              1,234  /  1.234  (로케일별 구분자)
{ratio, number, percent}     12%
{when, date, medium}
{price, number, ::currency/KRW}
```

**천 단위 구분자와 소수점이 로케일마다 다릅니다.**
독일어는 `1.234,56`, 영어는 `1,234.56`입니다. 직접 포맷하면 틀립니다.

## 텍스트 확장 — 길이 예산

영어 기준 번역문 길이 변화입니다. **업계 통용 어림값**이며 정확한 수치는 아닙니다.

| 영어 원문 길이 | 확장 여유 |
|:---:|:---:|
| 1~10자 | **200~300%** |
| 11~20자 | 180% |
| 21~30자 | 160% |
| 31~50자 | 140% |
| 51자 이상 | 130% |

**짧은 문자열이 가장 많이 늘어납니다.** 버튼 라벨이 위험합니다 —
"OK"(2자)가 독일어에서 여러 배가 될 수 있습니다.

| 방향 | 언어 |
|------|------|
| 크게 늘어남 | 독일어 · 핀란드어 · 러시아어 · 폴란드어 |
| 비슷함 | 프랑스어 · 스페인어 |
| **줄어듦** | **한국어 · 중국어 · 일본어** (영어의 50~70%) |

### 설계 규칙

- **버튼·탭 라벨을 고정 너비로 만들지 마세요.** 최소 너비 + 자동 확장으로 둡니다
- **CJK가 짧다는 것도 문제입니다.** 한국어 기준으로 잡은 레이아웃에 독일어를 넣으면 넘칩니다.
  **가장 긴 언어를 기준으로 설계**하거나, 줄바꿈을 허용해야 합니다
- **말줄임(`…`)에 의존하지 마세요.** 핵심 정보가 잘립니다

## 본문 글자 크기 — 코퍼스에서 확인된 사실

`design-systems/`에서 실측한 값입니다.

| 시스템 | 본문 기본 | 문자 환경 |
|--------|:---:|------|
| Ant Design | **14px** | 중화권 |
| Material 3 (Body Medium) | 14px | 크로스 플랫폼 |
| Helios | 13~14px | — |
| Canvas · Paste · Codex | 16px | 서구권 웹 |
| Apple iOS (Body) | **17pt** | — |

**16px은 서구권 웹 관행일 뿐 보편이 아닙니다.**
자소 밀도가 높은 CJK에서 14px이 흔하게 쓰입니다.

**다국어 대응 시 이 차이가 레이아웃 전반에 영향을 줍니다.**
14px 기준으로 잡은 화면에 16px 서구권 값을 그대로 넣으면 줄 수가 달라집니다.

자간도 갈립니다 — `design-systems/patterns/typography.md`에 정리돼 있습니다.
**Apple과 Material 3이 자간 방향이 정반대**이므로, 크로스 플랫폼에서 한 값으로 통일할 수 없습니다.

## RTL — 오른쪽에서 왼쪽

아랍어 · 히브리어 · 페르시아어 · 우르두어.

### 뒤집히는 것

- 텍스트 정렬, 읽기 순서
- 레이아웃 방향 (사이드바 위치, 아이콘·라벨 순서)
- **방향성 아이콘** — 뒤로/앞으로 화살표, 진행 표시
- 시작/끝 여백 (`margin-left` → `margin-inline-start`)

### 뒤집히지 않는 것

- **시계·재생 컨트롤** — 재생 버튼은 항상 오른쪽을 향합니다
- **숫자·전화번호** — 아랍어 문장 안에서도 좌→우
- 로고, 브랜드 자산
- 실제 방향을 나타내는 지도·차트

### 구현

```css
/* ❌ */  margin-left: 16px;   padding-right: 8px;
/* ✅ */  margin-inline-start: 16px;   padding-inline-end: 8px;
```

**논리 속성(logical properties)을 쓰면 RTL이 자동으로 처리됩니다.**
`left`/`right`를 쓰면 로케일별 오버라이드를 따로 관리해야 합니다.

## 번역하지 않는 것

파일에 `doNotTranslate` 목록을 두고 관리합니다.

- 브랜드명·제품명
- 코드·식별자·URL
- 단위 기호 (`px`, `MB`) — 다만 **날짜·통화·숫자 포맷은 로케일별로 바뀝니다**
- 플레이스홀더 자체 (`{count}` · `{userName}`)

## 파일 형식

**JSON + ICU MessageFormat**을 권합니다.

```
i18n/
  ko-KR.json
  en-US.json
  ja-JP.json
```

```json
{
  "home.cta.primary": "시작하기",
  "home.item_count": "{count, plural, other {#개 항목}}",
  "checkout.error.card_declined": "카드가 거절되었습니다."
}
```

**플랫한 점 구분 키**를 씁니다. 중첩 객체는 도구 연동과 diff가 불편합니다.

파일 예시:

| 파일 | 용도 |
|------|------|
| `template.json` | 빈 템플릿 |
| `en-US.json` · `ko-KR.json` | 작성 예시 (같은 키 집합) |
| `kr.json` | **의도적 위반 예시** — 린터 동작 확인용 |

`kr.json`에 심어둔 위반: 잘못된 로케일 코드(`kr`), 대문자 키(`Home.CTA`),
한글 키(`닫기`), 한국어에 불필요한 `one` 카테고리, 닫히지 않은 중괄호.

### 메타데이터가 필요하면 별도 파일로

번역자용 맥락 설명은 문자열 파일에 섞지 말고 분리합니다.

```json
{
  "common.action.close": {
    "context": "버튼 라벨. 동작(닫기)이며 상태(마감됨)가 아님",
    "maxLength": 6
  }
}
```

## 검사 스크립트

`lint.mjs` — 규약 위반과 번역 누락을 검사합니다. 의존성 없음, Node 18+ / Bun.

```bash
node lint.mjs ko-KR.json                        # 단일 파일
node lint.mjs ko-KR.json --against en-US.json   # 기준 대비 비교
node lint.mjs *.json --strict                   # CI용
```

**`--against`에는 영어 파일을 넣으세요.** 길이 예산 표가 영어 원문 기준입니다 —
한국어를 기준으로 삼으면 한국어가 원래 짧아서 다른 언어가 항상 초과로 잡힙니다.
스크립트가 기준이 영어가 아닐 때 경고를 냅니다.

검사 항목:

- **키 명명** — 소문자 스네이크케이스 + 점 구분인가
- **로케일 코드** — 파일명이 BCP 47인가 (`kr`·`cn`·`en_US` 검출)
- **ICU 문법** — 중괄호 균형, `plural`/`select`에 `other` 존재
- **복수형 카테고리** — 해당 로케일에 필요한 카테고리가 다 있는가
  (한국어는 `other`만, 아랍어는 6개)
- **플레이스홀더 일치** — 기준 파일과 `{...}` 집합이 같은가
- **문자열 이어 붙이기 흔적** — `" + "`, 하드코딩된 복수 분기
- **길이 예산** — 기준 대비 확장률이 위험 구간인가
- **번역 누락** — 기준에 있고 대상에 없는 키
- **미번역 잔존** — 값이 기준과 동일한 키 (복사만 된 상태)

`--strict`면 위반 시 종료하므로 CI에 걸 수 있습니다.

## 범위 밖

**특정 제품의 번역 문자열은 이 저장소에 두지 않습니다.**
여기 남는 것은 규약·템플릿·검사 스크립트뿐입니다.

번역 파이프라인(TMS 연동·기계번역 전처리)도 범위 밖입니다 —
필요해지면 별도 모듈로 분리합니다.
